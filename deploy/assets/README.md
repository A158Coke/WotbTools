# Alibaba Shanghai asset origin

This directory declares the Komodo-managed static origin for Agent 3D assets.
It does **not** cut production traffic over by itself.

## Runtime ownership

- Komodo Server: `ali-sh-asset-01`
- Stack: `wotbtools-asset-origin`
- Public name: `assets.wotbtools.com`
- Compose source: GitHub is review authority; Gitee is transport for the mainland worker.
- Source mirror gate: `.github/workflows/asset-origin.yml` force-mirrors `main` and then requires Gitee `main` to equal the exact reviewed GitHub SHA.
- Periphery lifecycle: the Alibaba target under `deploy/periphery/targets/ali-sh-asset-01/` uses the shared repository-owned install/reconcile/verify implementation; `.github/workflows/komodo-periphery-ali.yml` is its SSH transport job.
- Payload: host state under `/srv/wotb-assets`, mounted read-only into Caddy.

The asset pack is generated by `WoT-Blitz-Agent`; this repository does not own or build the game assets.

## One-time host adoption prerequisite

The Alibaba host was manually onboarded before it was added to the repository-owned
Periphery lifecycle. Before merging/enabling the production lifecycle workflow, finish
that one-time adoption on the already-connected host:

1. Configure key-only SSH for the `admin` operator and repository secrets
   `ALI_ASSET_VPS_HOST`, `ALI_ASSET_VPS_USER`, `ALI_ASSET_VPS_PORT`, and
   `ALI_ASSET_VPS_SSH_KEY`.
2. Ensure `admin` has the reviewed non-interactive sudo capability needed by the
   shared Periphery reconcile.
3. Create `/opt/wotb-asset` and `/opt/wotb-asset/periphery` as real directories
   owned by `admin`, and create the real `/opt/wotb-asset/.deploy.lock` owned by
   `admin`. The Periphery lifecycle deliberately refuses to create another owner's
   host mutation lock.
4. Re-prove the existing service is active, its process has **no** onboarding
   credential, `/etc/komodo/keys/periphery.key` and `core.pub` exist, and the
   outbound connection is logged in to Core.
5. Only after that proof, commit the repository lifecycle's durable marker as the
   root-owned mode-0600 file `/etc/komodo/keys/onboarding-complete` containing exactly
   `komodo-periphery-onboarding-v1`.
6. Run the Alibaba Periphery workflow once and require a credential-free successful
   reconcile. From that point onward binary/config/unit drift and future version
   upgrades are repository-owned rather than manual.

The marker contains no credential. It records that the *already completed* bootstrap
was independently verified before repository adoption. Never create it on a host that
has not already completed onboarding successfully.

## Host layout

Publish immutable releases and switch the `current` symlink only after the new release is complete:

```text
/srv/wotb-assets/
  releases/
    <pack-id>/
      index.json
      manifest.json
      glb/
      map/
      tank/
      tank_images/
      data/
  current -> releases/<pack-id>
```

Keep the current release plus at least one previous release while the migration is being proven. Do not overwrite the live tree in place.

## First rollout

1. Complete the one-time Periphery adoption prerequisite above and require the managed Alibaba Periphery reconcile to pass.
2. Merge the reviewed GitHub change and require the **Asset Origin Source Mirror** workflow to pass. Its exact-SHA check is the gate that proves the Gitee transport contains the reviewed commit; an informal/manual freshness check is not sufficient.
3. In ResourceSync `wotbtools-main`, review the pending diff. The existing `ali-sh-asset-01` Server and `wotbtools-asset-origin` Stack must be adopted by name; `address` stays empty and no inbound Periphery `:8120` is introduced.
4. Apply the ResourceSync diff. This must not deploy the Stack (`deploy = false`).
5. Stage the asset pack under `/srv/wotb-assets/releases/<pack-id>`, verify `manifest.json`, then atomically point `current` at that release.
6. Ensure Alibaba firewall allows public TCP 80/443. Do not expose Periphery 8120.
7. Point `assets.wotbtools.com` at the server when ready for certificate issuance, then explicitly deploy the Stack in Komodo.
8. Run `bash deploy/assets/verify.sh https://assets.wotbtools.com`.
9. Canary the Web client with `?assets=https://assets.wotbtools.com` before changing the production `ASSET_BASE_URL`.
10. Migrate the Android native asset origin in a separate client change. Old Android binaries keep using the old COS origin until retired.

## Caddy config/redeploy contract

`Caddyfile` is a tracked Komodo Stack config dependency with `requires = "redeploy"` for
the `caddy` service. Full/manual Stack deploys also pass `--force-recreate`, so a
Caddyfile-only CORS/cache change cannot report a successful deploy while the old Caddy
process remains in memory. The Caddy admin API stays disabled.

## Cache/CORS contract

Current filenames are not content-addressed. Caddy therefore uses a short revalidation TTL, not `immutable`. Browser CORS reflects only `https://wotbtools.com` and `https://www.wotbtools.com`. `Vary: Origin` is emitted unconditionally on cacheable responses so a shared cache cannot reuse a no-Origin representation for an allowed browser request. Range and conditional requests are served by Caddy's static file server; CI exercises the real Caddy image at request level, and `verify.sh` checks the externally visible behavior with bounded network timeouts.
