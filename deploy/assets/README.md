# Alibaba Shanghai asset origin

This directory declares the Komodo-managed static origin for Agent 3D assets.
It does **not** cut production traffic over by itself.

## Runtime ownership

- Komodo Server: `ali-sh-asset-01`
- Stack: `wotbtools-asset-origin`
- Public name: `assets.wotbtools.com`
- Compose source: GitHub is review authority; Gitee is transport for the mainland worker.
- Payload: host state under `/srv/wotb-assets`, mounted read-only into Caddy.

The asset pack is generated by `WoT-Blitz-Agent`; this repository does not own or build the game assets.

## Host layout

Publish immutable releases and switch the `current` symlink only after the new release is complete:

```text
/srv/wotb-assets/
  releases/
    <pack-id>/
      index.json
      manifest.json
      glb/
      map/
      tank/
      tank_images/
      data/
  current -> releases/<pack-id>
```

Keep the current release plus at least one previous release while the migration is being proven. Do not overwrite the live tree in place.

## First rollout

1. Merge the reviewed GitHub change and confirm the same commit/content is present on the Gitee transport mirror before Komodo deploys it.
2. In ResourceSync `wotbtools-main`, review the pending diff. The existing `ali-sh-asset-01` Server and `wotbtools-asset-origin` Stack must be adopted by name; `address` stays empty and no inbound Periphery `:8120` is introduced.
3. Apply the ResourceSync diff. This must not deploy the Stack (`deploy = false`).
4. Stage the asset pack under `/srv/wotb-assets/releases/<pack-id>`, verify `manifest.json`, then atomically point `current` at that release.
5. Ensure Alibaba firewall allows public TCP 80/443. Do not expose Periphery 8120.
6. Point `assets.wotbtools.com` at the server when ready for certificate issuance, then explicitly deploy the Stack in Komodo.
7. Run `deploy/assets/verify.sh https://assets.wotbtools.com`.
8. Canary the Web client with `?assets=https://assets.wotbtools.com` before changing the production `ASSET_BASE_URL`.
9. Migrate the Android native asset origin in a separate client change. Old Android binaries keep using the old COS origin until retired.

## Cache/CORS contract

Current filenames are not content-addressed. Caddy therefore uses a short revalidation TTL, not `immutable`. Browser CORS reflects only `https://wotbtools.com` and `https://www.wotbtools.com`. Range and conditional requests are served by Caddy's static file server; `verify.sh` checks the externally visible behavior.
