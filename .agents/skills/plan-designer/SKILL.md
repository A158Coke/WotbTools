# Plan-Designer（开发方案设计）

> 定位：把「要做什么」变成「怎么做、影响什么、如何验收」。前置：需求边界已清楚
> （grill-me 的《需求确认单》或用户明确表述）。本技能被调用时**自动先执行 grill-me**。

## 自动前置：grill-me（调用本技能时强制执行）

1. 完整读取 `.agents/skills/grill-me/SKILL.md` 并按其流程完成需求澄清：复述理解 →
   逐层提问（每轮 ≤3 个，按重要度排序，附默认答案）→ 输出《需求确认单》写入
   `docs/current-plan.md`。
2. 若需求已明确（`docs/current-plan.md` 已有《需求确认单》，或用户已明确表述
   目标/范围/非目标/验收标准），可跳过 grill-me，并在方案中注明「需求已明确，跳过前置 grill-me」。
3. 需求存在阻塞性分歧时停下等用户答复；非阻塞项用默认假设推进并标注「默认」。

## 流程

1. **可落地性核对**：需求与现有架构/约定是否冲突？用 `rg` / `rg --files` 找现有实现与引用，
   必须引用具体 `文件:路径` 与 `文档:章节`，禁止凭印象。
2. **影响面扫描**（按 wotb-sync 检查单逐层过）：解析 → 模型 → API → 前端 locale → 导出
   （`Columns.java` / `AggregateSheets.java`）→ 测试 → 文档 → 构建/部署。逐项标 ✓ / ✗。
3. **方案设计**：分步实现，每步可独立验证；明确**不做清单**（防过度设计）；给出验收标准与测试路径。
4. **风险与默认决策**：列出不确定点；能从文档/代码推断的直接决策并注明依据；
   剩余影响用户可见行为/成本/破坏兼容的关键决策列给用户确认。
5. **输出《开发方案单》并写入 `docs/current-plan.md`**（与 k3-planner 计划格式兼容）：
   目标 / 方案概要 / 分步计划（文件清单 + 改动要点 + 验证方式）/ 影响面清单 / 不做清单 /
   验收标准 / 待确认项。
6. **交给 Plan**：方案单写入计划文件后即 Plan 素材，等待用户批准后才进入编码。

## 规则

- 只用证据说话：引用 `文档:章节` 与 `文件:路径`；无法从事实源确认的写「待确认」，不猜。
- 不写实现代码；方案获批后才开发。
- 与 `review-with-docs` 的分工：本技能开发前（需求/方案设计），`review-with-docs` 开发后
  （变更审查 + 文档同步）。

## current-plan.md 结构示例 

### 1. Business Contract
用户最终应该获得什么。

### 2. Technical Contract
真实数据源、API、数据结构、实现边界。

### 3. UX / Visual Contract
只在涉及 UI 时存在。

### 4. Verification Contract
必须怎么证明做完了。
