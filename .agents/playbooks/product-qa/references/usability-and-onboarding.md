# UI/UX 与教程：任务驱动检查

在 `usability-and-onboarding` 场景读取。本文件补充主技能的黑盒、授权与复现规则，不放具体线上 bug 清单。

## 任务与证据

依据页面提示找入口并为各模块建立真实用户目标。例如：用官方示例理解一局比赛、定位关键时刻并标记、选择数据列后导出、查一辆坦克的参数。默认全站运行覆盖完整功能清单，不能用少量任务代表整个网站；仅用户明确缩小范围时才减少模块。

对每个任务记录：

| 项目 | 记录内容 |
|---|---|
| 用户目标 / 起点 | 首访或回访、匿名或测试账号、有无自选回放、viewport、locale |
| 实际路径 | 入口、关键点击/输入、返回、重复确认、必要滚动；有实际记录才给步骤数或耗时 |
| 结果 | 成功 / 成功但需绕行 / 被阻断 / 主动跳过 / 未测 |
| 阻力 | 看不懂、找不到、反馈不符、操作被遮挡、状态丢失等可观察事实 |
| 恢复 / 证据 | 关闭、返回、重试、重开能否恢复；关键前态与后态截图 |

先跑普通用户路径，再以已观察到的阻力做短验证。先前知道的问题只作为后续回归，不让整轮探索变成寻找旧结论。Agent 的启发式检查不等于真人受试实验。

## 首次进入与独立完成

- 用全新 browser context 测首次进入，保留它作为本轮会话；再用回访会话区分“首次提示”和“重看入口”。不得读取或直接清除站点内部存储制造状态。
- 记录入口是否直接表达任务，是否清楚说明示例/个人文件、登录要求与本地文件保留边界。
- 教程结束或跳过后，独立完成一个实际目标，如增减列后成功下载。只打开导出菜单不算导出成功；收到下载事件不等于文件内容或安装已验收。
- 不预设教程必须采用某种视觉样式。只有入口、提示或布局具体影响任务时才报问题。

## 教程主线与支线

主线从欢迎页走到完成页；全站模式还需执行所有可见支线，只有专项模式才可选一条相关支线。每个关键步骤至少记录“提示要求 → 目标控件 → 实际操作 → 可见反馈”。

| 检查面 | 具体操作 |
|---|---|
| 跟着做 | 播放/暂停、选择工具并实际画一次、选择射击记录；核对真实状态变化，而非只点下一步 |
| 返回 | 下一步后上一步，确认当前页面、提示、目标与选中状态匹配 |
| 跳过 / 完成 | 中途跳过与最终完成分别测试；检查残留蒙层、控件可用、完成页 CTA 与重开入口 |
| 自选文件 | 用 fixture 建立已有回放，进入教程；记录替换提示与确认次数，拒绝替换时检查原文件是否可继续使用 |
| 初次加载 | 正常等目标就绪后操作；另外测试提示允许时在准备中点下一步，不用网络拦截制造慢网 |
| 重试 | 出现 fallback 时，核对实际控件是否真的不可用；点重试，检查数据/目标是否恢复，不只看提示消失 |
| 登录 | 有授权身份时，从需要登录的支线正常登录，检查返回视图、示例、步骤和用户目标是否接续 |

教程显示“完成”不代表所有子操作均完成。记录主动跳过的 3D 启动、生成、命中检视等项目；遵守本仓视觉验收边界，不将 headless 场景截图当作真实 GPU 渲染验收。

注意教程、文件替换确认、列面板、射击详情可能叠加。记录操作时最上层是什么，不因旧步骤还在可访问性树中就认定用户看见了它。

## UI 与易用性维度

| 维度 | 判断依据 |
|---|---|
| 发现与理解 | 按钮名、同屏提示和结果是否一致；关键含义有解释；无裸露内部 key / 原始格式符号 |
| 反馈与控制 | 选择、加载、成功/失败、禁用状态能否对应实际操作；可取消/重试，重复点击反馈合理 |
| 任务成本 | 重复确认、同义入口、无意义往返、必须重做的输入；说明实际增加的操作，不凭感觉打分 |
| 布局与阅读 | 标题层级、长文/长表、换行、截断、固定导航、说明卡片和触点是否遮住任务控件 |
| 键盘与弹层 | Tab / Shift+Tab 顺序和可见焦点；Esc 关闭最上层后是否误退出底层教程；关闭后能否继续 |
| 移动端 | 竖屏、必要的横屏；目标可触达、面板可滚动、滚动后能找回操作栏；触控模拟不能代替真机 |
| 连续性 | 返回、刷新、教程重开、登录回跳后的路径是否可理解；本地文件刷新丢失需结合产品提示判断 |

检查层级、对比度、触点时，用可见阻力支持判断；未经测量不声称满足/违反某项可访问性标准。

## 浏览器操作与误报排除

- 根据当前可访问性信息选 `button/radio/link/menuitem` 等角色。失败后观察页面，避免反复猜控件角色、读取组件源码或测试专用属性来绕开用户入口。
- 纯文本快照不能区分标题和操作按钮。声称页面只有标题、缺少入口前，核对可访问性角色并查看截图，再操作实际可见入口；不能因等待了错误的按钮名就认定加载失败。
- 点击可能先更新路由、后更新提示；等新步骤标题和目标就绪再截图。瞬时旧 snapshot 不能证明步骤错配。
- 产品问题与自动化问题分开：错误 locator、range 的不合法 fill 值、导航等待 `load` 超时、headless 的 Esc 行为、窗口未激活，都应先核验。
- 标准浏览器 `back/forward/reload`、键盘、真实 file chooser、触控/鼠标操作均可用；不 force click，不注入产品状态，不伪造接口响应。
- 截图应保留足够上下文：viewport、教程标题/进度、目标控件、出现问题的弹层。用浏览器截图保存并实际查看；只读 aria 文本无法证明遮挡。
- 将稳定问题、加载瞬态和仍不清楚预期的行为分列。重复生成、缓存重入、刷新重导是不同复现条件，分开记分母。

## 收尾与经验沉淀

报告按任务影响排序，优先阻断、误导和恢复成本，再写布局细节。每个 finding 给出可验收建议，例如“关闭最上层面板后仍保留教程当前步骤”，避免泛泛的“优化 UI”。

更新 skill 时只吸收本轮有依据的方法改进，如缺少的状态组合、证据标准或工具排障。具体 bug、账号、截图与报告留在运行记录中；未经复测的旧 finding 不当成当前事实。保存覆盖空白，不能为凑问题数降低复现标准。
