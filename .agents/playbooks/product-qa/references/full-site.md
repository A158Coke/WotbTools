# 全站 QA：功能清单与执行契约

这是 product-qa 的默认范围。以真实浏览器建立覆盖清单，再完成所有可达、已授权用例；不是访问所有导航后就算测试整个网站，也不是穷举无限数据和所有组合。

## 1. 从 UI 建立清单

从匿名首页、更多、页脚、登录后账户与管理导航逐层发现入口。每个页面继续清点标签、筛选、排序、搜索、详情、分页、导入/导出、菜单、对话框和教程。进入新页面发现新功能就补清单。不要从源码、路由文件或 issue 反推产品行为。

以下是起始检查域，实际界面为准；不可达或不存在也要注明观察：

| 域 | 应清点并操作的功能 |
|---|---|
| 首页与全局 | 首页卡片、主导航/收起/更多、页脚、主题、三语、反馈/联系、历史/技术/文档、赞助展示 |
| 回放数据 | 3 个 fixture、单/多文件与文件夹、追加/重复/清空、取消/错误、汇总/单场、列与排序、Rating 说明、各导出项及内容验证 |
| 2D | 播放暂停、快进退、速度、seek/结尾、名单/详情、显示设置、地图切换、标记/撤销/清空、防遮、全屏、多回放切换 |
| 3D 与射击 | 入口/登录门槛、画质/准备/开始、控制与选车、退出/重入；射击者/逐发/详情/查看器/返回。GPU 视觉按仓库规则标 MANUAL |
| AI | 登录门槛、选择/切回放、生成/阶段反馈、取消/重试、最终结果、折叠/复制/相关跳转；标明生成范围和成本，避免无必要反复生成 |
| 名人堂 | 各榜单/筛选/搜索/排序/分页、记录详情与回放入口、个人记录、提交入口与校验；公开写入受授权边界约束 |
| 坦克百科 | 搜索/过滤/排序/加载更多/无结果恢复、参数、装甲入口和参数控件；模型视觉 MANUAL |
| 赛事积分 | 赛事/阶段/分组切换、榜单/详情、导出/空状态；管理录入、规则、发布单独列项 |
| 直播回放 | 服务器/赛季/子赛事、筛选、列表与详情、链接入口/返回/空状态；管理创建/编辑/删除单独列项 |
| 推荐内容 | 分类/筛选/详情/外链、无数据恢复；管理列表/查询/表单单独列项 |
| 账户认证 | 登录/登出/回跳、资料/复制、绑定与安全入口、普通和管理角色可达性；第三方外部身份流程单独记限制 |
| 管理后台 | 所有实际可见管理项：列表/查询/筛选/分页、详情、表单打开/取消/可安全验证的输入校验；保存/发布/删除/角色变更单独列项 |
| Android | 匿名/登录下载、版本信息、下载成功/失败反馈；安装、真机与更新链标明设备限制 |
| 教程 | 主线与全部可见支线、真实目标操作、前进/返回/跳过/完成/重开、自选文件替换、加载中前进、fallback 重试、登录恢复 |

全量不是允许越过生产写入边界。把“管理列表可用”和“保存/删除功能未执行”拆成不同用例；对不宜在生产执行的用例标 BLOCKED 并写出需要的隔离环境/授权/测试数据，不伪装为 PASS。已有授权持续有效，不因换轮或分区重复索取。

## 2. 逐功能 ledger

在仓库外本轮证据目录维护 Markdown/JSON 均可，每个可验证动作一行：

| ID | 模块 / 功能 | 身份 / 数据 / 尺寸 | 操作与预期 | 实际观察 | 状态 | 证据或阻碍 |
|---|---|---|---|---|---|---|

状态只用：

- `PASS`：实际操作，观察结果满足明确预期。
- `FAIL`：已执行但观察异常；尚未独立复现的 finding 仍放 Needs investigation，不能因用例 FAIL 自动建 bug。
- `BLOCKED`：缺少身份、数据、外部能力或写操作授权；写具体前提和下一步。
- `MANUAL`：依仓库规则或设备要求需用户/真机验收；不能以 headless 截图替代。
- `UNTESTED`：清点了但尚未执行；继续推进，不能在结尾藏进一句“部分未覆盖”。

分别统计功能执行和状态。分母含 BLOCKED/MANUAL/UNTESTED，不把它们删掉来制造 100%。若写百分比，解释公式；“可执行用例已跑完”与“所有功能通过”严格分开。已有报告可用于后续回归，不当作本轮 PASS。

## 3. 横向维度

每个主模块都检查桌面与手机关键任务，三种语言和主题的切换/持久性及主要页面文案；组件代表状态和特殊长表/长文/管理表单均纳入。记录实际组合，不能声称已穷举所有浏览器、角色、语言、设备排列。

每个主要流程包含正常路径、重复/切换、返回/刷新，以及可安全触发的空/错误恢复。弹层加入键盘 Tab/Shift+Tab/Esc；教程加入实际操作而非只下一步。下载需区分启动、完整文件、内容正确和安装成功。

**有浮层的模块必须跑主技能 §4 的遮挡 / 可达矩阵**（常驻工具栏 + 菜单开、sticky 表头 + 下拉开、
列表展开 + 浮层开、底栏 + sheet 开、drawer + 背景 sticky、断点切换、全屏 + 浮层开），
手机竖屏与**横屏**各一轮，并用 §1 例外里的只读几何探针留下数值。静止初始态截图不算执行过这一项。

## 4. 分工与持续执行

按适用仓库要求拆分大任务时，各分区独立浏览器 context、截图子目录、ledger 和报告；不能共享登录资料或读写彼此的 page。主代理负责检查状态与产物、补重复/空白覆盖，再汇总。不要为了并行覆盖创造相互冲突的生产写操作。

每完成一个模块保存 ledger 和后续清单。长运行中断时从已验证的行恢复，不重新把所有页面跑一遍，也不把上下文限制作为改称完成的理由。

## 5. 完成判据

- 全部可见模块、详情、操作和教程已入清单；本轮新发现的入口已归属。
- 所有可达且已授权用例已执行，`UNTESTED = 0` 才能称“本轮清单执行完毕”。
- 有浮层的模块都跑过遮挡 / 可达矩阵（含手机横屏）并留下探针数值；缺这一项同样不能称执行完毕。
- 每个 FAIL 与受阻/人工项可追踪到证据或具体前提；确认问题达到主技能独立复现门槛。
- 报告给出全部状态计数、分区结果、未覆盖组合与人工验收项；有 BLOCKED/MANUAL 就明确“未实现所有功能全验证”，不称无条件 full pass。
- 未经本轮实际运行的历史问题与本轮发现分开；不自动创建 issue 或修改产品代码。
