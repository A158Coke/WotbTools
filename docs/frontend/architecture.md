# 前端架构

## 当前基础

产品使用遥测在 `AppShell` 中只有唯一的前台生命周期所有者（`useUsageTelemetry`）。它观察规范的 router view（包括 workspace 能力路由）；仅在 query 中变化的 tank/file/filter 改动不会重新打开某个功能。Replay Data 没有 page-open 事件：`useLocalReplayAnalysis` 对每个选中文件记录一次 start 和至多一次 terminal，并使用 `parseReplayFiles.onFile` 处理部分批次完成。取消只会结算尚未完成的文件。只有 attempt UUID、枚举后的 outcome 和安全错误类别会离开客户端；文件名、内容和原始错误保留在本地。

已登录活动在前台初始化/恢复、认证就绪，以及前台且在线时每五分钟发送一次。API transport 在发送前刷新 token 并重新检查 account epoch/前台所有权；服务端校验 bearer 并推导账户身份。匿名 feature/parse 事件使用最大 100 条事件的内存队列、每批 20 条事件和五秒 flush；失败的上传会被丢弃，不做磁盘持久化，也不自动重试。浏览器刷新/离线使用/进程终止可能丢失遥测。不引入持久化匿名标识符或精确的匿名用户计数。Android 打包同一个 producer；较旧的 APK 仍可使用，只是不会贡献这些新事件。

新手引导在 AppShell 中只有一个 `useOnboarding` 所有者，`OnboardingHost` 消费该 controller；跨层接入只用共享类型化的 `ONBOARDING_KEY`，Workspace 和各 pane 保留业务状态并注册明确 commands/readiness。指南无独立路由或第二个 replay renderer，见 [功能契约](../features/onboarding.md)。

`main.js` 在导入 router 或重写 localhost 预览 URL 之前先守护 Web OIDC 返回。当 query 或 fragment 同时包含 `state` 与 `code` 或 `error` 时，它会等待现有 `useAuth().initPromise` 的结算信号；只有 keycloak-js 会校验并消费该 callback。只有此后才会基于 adapter 产生的最终 URL 构造 `createWebHistory`，并规范化 legacy view aliases。成功的 fragment callback 会在 router 对 history 做快照之前被消费。在 incoming callback 初始化期间，provider 会守护 SDK 的公共 `login` 方法，并在没有 silent redirect URI 的情况下启用 `onLoad: 'check-sso'`。SDK 判定有效的 callback 会绕过 `onLoad`；因此匹配的 `prompt=none` / `error=login_required` 返回会正常结算为未认证。缺失 transaction 的情况则会进入受守护的 fallback，并在任何新的 SSO transaction 能够掩盖原始失败之前失败。被 SDK 拒绝或已过期的交互式 callback 同样需要显式恢复。init 结算后会恢复原始 login 方法；普通访问仍保留其正常的 `check-sso` 配置。provider 仍使用 SDK 默认的 fragment 响应模式：识别看起来像 query 的 URL 只会延迟路由，并不会增加 query-mode 支持。这种存在性检查从不授予认证。拒绝与现有的 12 秒 Web watchdog 都会进入既有的 failed-auth UI；结算本身并不保证每个格式错误或超时的 URL 都已被清理。普通访问在 `check-sso` 运行时仍会渲染；APK 启动仍由 Native 拥有，不等待这条 Web callback 路径。legacy alias 重定向会保留无关的 query 值和 hash，包括普通页面锚点。

应用根组件 [`frontend/src/App.vue`](../../frontend/src/App.vue) 只渲染 Vue Router 的 outlet。应用关注点位于 `frontend/src/app/`：

```text
App.vue
  → app/router.js
  → app/AppShell.vue
      ├── AppSidebar.vue     # 平板 / 桌面（≥ 768）：左侧边栏主导航（含 MorePanel 弹出面板）
      ├── AppTopBar.vue      # compact（< 768）：标题栏
      ├── ViewHost.vue       # <main>，按 ?view= 渲染页面
      ├── AppTabBar.vue      # compact（< 768）：底部主导航
      └── GlobalErrorDialog.vue
```

主导航的唯一数据源是 `app/navigation.js`：`PRIMARY_NAV` 定义首页 · 回放 · 名人堂 · 坦克百科 · 科技树 · 联赛积分榜 · 联赛直播回放 · UP 推荐 · 更多（**科技树与坦克百科平级**，各自是独立栏目：`agent-techtree` → section `techtree`，顶栏/标题显示「科技树」，侧栏与底部栏各有一项；不挂在坦克百科之下），`primaryNavItems()` 再按 runtime/host 投影实际可见项——public Web home host 保留首页，Android APK 与本地 Web 不显示首页并以回放作为默认落地页；`ADMIN_NAV`（按角色显示的管理入口）与 `primarySection(view)`（视图归属哪个栏目）共享同一导航模型。外壳按 `useBreakpoint()`（`composables/useBreakpoint.js`，断点常量在 `shared/breakpoints.ts`）在两种形态间切换：平板 / 桌面渲染 `AppSidebar`（桌面可折叠，偏好由 `composables/useSidebar.js` 写到 `<html data-sidebar>`，`tokens/scale.css` 据此派生 `--sidebar-w`）；手机渲染 `AppTopBar` 标题栏 + `AppTabBar`。两者都用 `RouterLink` 渲染，并以 `aria-current` 标记当前栏目。直播入口的 `shortLabelKey` 仅用于底部栏和侧栏收起形态，完整名称仍为辅助技术提供；桌面展开形态与页面标题使用完整名称。账户（登录、个人中心、登出）进入 `?view=profile`（`ProfilePage.vue`，未登录时显示说明卡而不是自动跳转）：平板 / 桌面在侧边栏底部，手机在标题栏右侧。"更多"的内容只有一个来源 `composables/useMoreMenu.js`：平板 / 桌面是侧边栏底部的弹出面板（`app/MorePanel.vue`：显示设置 + 关于与支持；管理入口在侧边栏管理组），手机是 `?view=more` 整页（`components/MorePage.vue`，另含按角色显示的管理入口）。

AI 复盘结果的反馈弹窗与复制按钮使用同一回复文本 formatter；提交会包含该完整文本。反馈管理视图由站点管理员导航和深链角色门保护，列表筛选、分页、详情和删除走 Business Backend；功能联网状态由 `AI_FEEDBACK` / `ADMIN_AI_FEEDBACK` capability 判定。

`router.js` 拥有浏览器 history、deep-link 处理、重定向和 Back/Forward。产品 URL 有意保留兼容的 query 契约：`?view=replay`、`?view=ai-review`、`?view=battle-playback`、`?view=agent-replay` 和 `?view=agent-shots` 都解析为同一个 keep-alive 的 Replay Workspace，只是初始能力不同（data / ai / playback / 3d / shots，见 `viewRegistry.js` 的 `replayInitialCapability`）。legacy aliases（`leaderboard`、`extended`、`reconstruction`）各自一次性重定向到其规范的 query 值。Android 还会把过时的落地 `?view=home` URL 规范化为 Replay-root URL，同时保留无关的 query/hash 值；公开 Web 的 Home deep link 仍然有效。`/download/android` 和 `/download/android/` 解析到 Android 页面；`/sponsor` 是 AppShell 的一等路由，经 `ViewHost` 解析到 `SponsorPage`。

**视图私有 query 键**（`navigation.js: locationForView`）：名人堂筛选（tab/page/nation/type/tier/bt/nick/limit）、坦克百科筛选与详情（q/tier/nation/type/sort/tank/config/engine/track/shell/dev/cons/prov/skills/camo/eq）、以及装甲查看器 / 射击复现场景参数（tank/shooter/config/scfg/sengine/strack/sdev/engine/track/dev/shell/shot/world/heatmap + 相机与显示档 az/h/d/eqcal/eqenh/quality/move/rel/clean/debug）只属于各自的视图：导航到别的视图时整组丢掉（`locationForView` 三条清理规则），否则从场景切走会在 URL 里留下上一发的 `tank/shot/shooter/…`。留在同一视图内的导航保留全部参数。

3D 回放与射击分析是工作台能力：`agent-replay` / `agent-shots` 深链与工作台 tab 都解析为同一个 kept-alive Replay Workspace 的 `3d` / `shots` pane，与 2D / AI 共用同一条 session（`props.file` 消费工作台已选回放，自身没有上传入口），并保留工作台上层导航。五个能力永久对所有用户展示，导航不按 admin role 收敛 Agent 深链。3D / shots 在匿名使用个人回放时显示 `ReplayCapabilityAuthGate`；登录或选择已验证的官方示例后才加载 pane；AI 在现有投影边界前门控。`test:browser-interaction` 用真实输入验证普通用户与匿名路径以及 shots → armor 交接。

AI Review 正常挂载：`?view=ai-review` deep link 与 workspace tab 都解析为同一个 keep-alive 的 Replay Workspace 及其 `ai` 能力，该 pane 在共享的 auth + local-projection 门控之后挂载 `AiReviewWorkspacePane.vue` / `AiReviewPanel.vue`（不存在前端维护门控；`ai_maintenance` locale 字符串没有消费者）。传输逻辑留在 `api/ai-review.ts`；AI 输入是客户端规范投影（`replay-local/ai`），后端是 Yecao ai-service（见 `docs/operations/ai-service.md`）。Replay 解析与 Battle Playback 仍可通过各自现有的 tabs 使用。

`app/viewRegistry.js` 是 view 名称的唯一事实来源：`VIEW_COMPONENTS` 将受支持的 query views 和由 path 派生的 views（`android`、`sponsor`）映射到各自组件。`app/navigation.js` 在其上拥有 deep-link 契约，未知 view 会回退到默认 view，因此 `ALLOWED_VIEWS` 必须与已注册的 view 名称保持相等——`frontend/src/App.test.js` 锁定这一相等性。新增或重命名 view 意味着要同时更新 registry、allowlist 及其导航入口；只改一侧会静默降级到默认 view，而不是显式失败。只有落地 views（`HomePage`、`ReplayWorkspace`）是立即导入的；其他每个 view 都是 `defineAsyncComponent` chunk，而在 workspace 内部，四个能力 pane（`BattlePlaybackPanel`、`Replay3DPane`、`ReplayShotsPane`、`AiReviewWorkspacePane`）经过 `utils/lazyModule.ts` 的 `defineLazyModule` 失败边界，因此确认过期的同源 `/assets/*` 404 会走 `platform/preloadRecovery.js` 中受守护的一次性 fresh-bundle reload 路径（共享 60s cooldown），而网络失败、5xx、未知状态、无 URL 的 dynamic-import 失败（无法安全关联）以及无法关联的失败都会保留既有的、可见且由用户控制的 `defineLazyModule` pane 内状态，而不是卸载 workspace。为这些模块提供 mock 的测试必须返回 `__esModule: true`，并用 `vi.dynamicImportSettled()` 等待。`main.js` 让 `<html lang>` 与 `document.title`（`<section> · WoTBTools`）保持与 locale 和 route 同步。

`ViewHost.vue` 将现有的扁平页面组件映射到由 route 派生的产品 view。扁平布局是当前实现；不要把另一种目录布局视为已经存在。不要给组件添加手动的 `history.pushState`、`replaceState` 或 `popstate` 监听器；应使用注入的导航命令，它会委托给 Vue Router。

应用导航由 `frontend/src/shared/navigation.ts` 中与 feature 解耦的类型化 `NAVIGATE_VIEW_KEY` 定义。`AppShell` 提供该命令；app 与 feature 消费者注入共享契约，而不导入 router 内部实现或 `app/` 实现模块。生产代码不得引入魔法字符串形式的 `inject('navigate')` / `provide('navigate')` 调用。外壳沉浸态同理使用 `shared/shellChrome.ts` 的 `SHELL_CHROME_KEY`：`AppShell` 提供并独占显隐状态，`ReplayWorkspace`（手机横屏回放就绪）与 `AgentArmorView`（手机横屏且 WebGL 可用）各自以自己的 owner token 申请 / 释放，`BattlePlayback` / `Replay3DPane` 只读。

积分赛管理入口由 `useAuth.isTournamentAdmin` 所有（真实 token 中的 `tournament-admin`，全站管理员通过 Keycloak 复合角色继承），不复用全站 `isAdmin` 放大专属角色权限。公开「联赛积分榜」是主导航栏目，位于坦克百科之后；主导航、页面/浏览器标题与导出标题共用 `tournament.title`，公开入口不重复放到更多面板/页面中。公开积分页持有正式 standings，`utils/tournamentPointsExport.ts` 提供屏幕/Excel/打印文档共享的列投影；`shared/tabular/xlsx/` 是唯一 ExcelJS renderer，feature 保留工作簿投影与打印文档；管理页的历史导入、预览和幂等提交状态仍归 `useTournamentPointsAdmin` 所有，JSON 文件只在文件边界转为 OpenAPI request，经 `api/tournament-points.ts` 发起请求。

## 依赖与状态规则

要求的依赖方向为：

```text
app → features → shared
```

当前源码树使用扁平的 `components/`、`composables/` 和 `utils/` 目录；依赖规则在概念上仍然适用，但不会声称存在实际不存在的 feature 目录。新工作不应建立跨 feature 的私有导入，也不应把 feature endpoint 知识放进 shared 代码。

每个业务状态只有一个权威所有者。Replay session 状态（selection、analysis state/results、workspace view state）由 `frontend/src/composables/useReplaySession.ts` 拥有；本地 parse → batch-compute → client-export 副作用由 `frontend/src/composables/useLocalReplayAnalysis.ts` 驱动（基于 `replay-local/parseReplays.ts` / `replay-local/analyzeReplays.ts`），而 `useReplay.ts` 将该契约作为 facade 暴露，`useReplayWorkspace.ts` 还拥有惰性 Playback session 结果，该结果由 2D、3D 与 Details 共享给 orchestration SFC 和 capability panels。不存在 Processing/Export job 状态（`useProcessingJob.ts` / `useExportJob.ts` 已移除——服务端没有 replay parser）。用 `computed` 派生值；只在真正的副作用或生命周期桥接中使用 `watch()`，绝不用它同步同一状态的重复副本。

核心 Replay/API/AI/Playback 契约位于 `frontend/src/types/`，并在外部 JSON/SSE 边界处校验。迁移期间 JavaScript 与 TypeScript 可以共存；`.js` import specifier 可能经 Vite/TypeScript resolver 解析到其 `.ts` 实现，但只能有一个实现。

业务 HTTP endpoint 的唯一 owner 是 `frontend/src/api/**`。`user-profile.ts` 持有用户资料、账号绑定与验证；`admin-users.ts` 持有管理用户搜索、详情与删除；`hall-of-fame.ts` 持有单场、百场、三环的公开/登录/管理请求、个人状态与证据上传下载；个人单场成绩 `getUserHofRecords` 也由该 owner 提供，`user-profile.ts` 不持有 HoF 请求。组件/composable 消费领域 API，资料 provisioning/retry 状态机仍归 `useBusinessUserBootstrap`。wire 类型以 generated OpenAPI transport 为准。

用户资料与账号绑定的六条请求、管理用户的搜索/详情/删除、名人堂单场的公开分页、个人成绩、公开/管理车辆选项、上传、管理列表与审计，百场与三环的公开/提交/取消/个人状态/管理 JSON，以及单场/百场/三环的批量删除结果，在 API owner 内将网络 JSON 视为 `unknown`，通过 generated OpenAPI runtime validator 后才返回 typed wire value。积分赛、推荐与联赛直播也在各自 API owner 完成校验与视图投影。上述边界的 JSON 语法错误或形状不符均抛出不可重试的 `INVALID_RESPONSE`，不补字段、不接受契约外 enum；合法 optional/nullable 值保持原样。HoF 数组先检查数组形状，再逐项使用 generated validator；空数组合法，非 nullable 的 `null` 或非法条目失败。三环按自身 DTO 定义状态和可空字段，不复用百场的业务 shape。

单场 `hofAdminDelete` 返回 `void`，不消费服务端成功 JSON；Blob 下载直接读取二进制；无内容响应保持各领域的 `null`/`void` 返回，不调用 `json()`。HTTP 200 的 JSON `null` 不能冒充 204。AI Review 的 SSE 继续由 `utils/aiReviewSse.ts` 校验事件协议，取消与遥测保持既有 best-effort 通知语义；静态/WASM/Native 资源不套用业务 JSON validator。

`frontend/src/utils/http.ts` 持有共享 transport、Android URL 解析、credentials、canonical ApiError 与错误归一化；其 path→feature 表仅为 defense-in-depth，不接管页面/composable 的产品 gate。静态地图/模型、官方示例回放、WASM fingerprint、APK manifest、Native/WebView 资源 fetch 不属于业务 HTTP endpoint 规则。`src/api/http-ownership.test.ts` 检查生产代码中的 endpoint literal，明确允许 API 目录及 `utils/http.ts` 基础设施例外，不禁止资源 fetch。

Replay HTTP 归属集中在 `frontend/src/api/` 下。`replay-capabilities.ts`（名称作为历史遗留保留）拥有共享的 Bearer/auth-session plumbing（`ReplayAuthSession`、`optionalBearer`、`authedReplayPost`），供仍然存在的服务端调用使用；`ai-review.ts` 拥有 AI Review SSE/HTTP transport；本地解析、batch compute、export 和 2D playback 没有 HTTP transport（`replay-local/**`），本地生成的 Playback V2 dataset 由 `contract-runtime.ts`（`validateBattlePlaybackDataset`）在边界处校验，而不是拉取。`AiReviewPanel.vue` 和 `BattlePlaybackPanel.vue` 只拥有 run/view 生命周期，不得重建 `apiFetch` / `authedReplayPost` plumbing，也不得硬编码 transport 调用。

Replay Workspace 的呈现被拆分为职责聚焦的子组件（`PageHeader.vue`、`ReplayCapabilityTabs.vue`、`FileDrop.vue`——全站唯一的文件入口——以及用于单场战斗能力的 `BattlePicker.vue`；状态与门控使用 `EmptyState.vue` / `Banner.vue`）。一个工作台承载全部五个能力（`data` / `playback` / `3d` / `shots` / `ai`）：`ReplayWorkspace.vue` 是唯一的能力编排者，并在首次激活时惰性挂载 `BattlePlaybackPanel.vue`、`Replay3DPane.vue`、`ReplayShotsPane.vue` 和 `AiReviewWorkspacePane.vue`（`composables/useMountedWhenActive.js`），在切换离开该能力时保持每个 pane 的 session 存活。三个单场战斗 pane 与 3D pane 共享同一个 `file` / `active` / `blockedReason` prop 契约；它们都不拥有文件选择器或第二个 session。`ReplayPage.vue` 内的 Data 结果工具栏使用 `SegmentedControl.vue`、`BattlePicker.vue` 和 `MenuButton.vue`；`SeriesOverview.vue` 渲染由 `utils/replaySeries.js` 派生的系列比分。Selection / analysis 状态 / 当前战斗仍由 `useReplayWorkspace()` / Replay session 拥有（本地 parse + batch compute 副作用经 `useLocalReplayAnalysis` 运行）。直接 parent-child 依赖是显式的：`ReplayWorkspace.vue` 将权威 replay session 和 workspace 呈现状态作为 props 传给 `ReplayPage.vue`，而不是把它们藏在 `provide('replay')` / `provide('replayWorkspace')` 之后。认证从现有的 `useAuth()` singleton 消费，而不是由 `AppShell` 通过字符串 service-locator keys 再导出。

装甲查看器（`agent-armor`）可匿名使用；个人回放的 shots 在 Replay Workspace 中仍受门控，而已验证的官方示例 shots 也可匿名使用。浏览器登录会保留完整的场景 query；普通已登录用户无需 admin role 即可使用 shot reconstruction。它仍是独立页面：它属于 Tankopedia 一侧，并保留自己的 URL 契约（`?tank= &shooter= &config= &shell= &shot= &world=1`）。Replay 工作台复用其*引擎*（穿透计算、坦克资源、`scene/tankViewer.js` 的 marker 调色板），而不是其页面导航模型——shot inspector 通过现有的 local handoff channel 交付 shot 数据，并要求 router 打开该目的地。

装甲厚度是**按配置限定的**：查看器从选中的 `tank/{id}.json` config 读取 `configs[].turret_plates`、`configs[].gun_plates` 和 `configs[].gun_thickness`。`armor_model` 仅保留为 top-config 摘要，不是 fallback 来源；缺失的 per-config plate 会 fail closed 到 0 mm。config 变化时，查看器会刷新 armor-plate cache、visual gun-barrel module cache、spaced classification 和当前 collision material colors；随后 heatmap 重建与 click judgment 读取这些刷新后的 cache。没有新的 asset-shape 契约，不得将 `armor_model` 恢复为 fallback。

穿透衰减（`penetration_far`，client 0x719740）的交战距离取决于模式：**shot replay 使用服务端解码的弹道路径长度**（`scene/agentData.js` 中的 `shotBallisticLength`：`ball_a → via… → ball_b` 折线总长，包含跳弹段——即炮弹实际飞行的距离），而**静态装甲检查使用 camera → 首个命中 plate 的距离**。两者都供同一 judgment 和 penetration-map uniforms 使用；结果卡片显示实际使用的值。装甲查看器中的 camera-click judgment 只对到达**主装甲**的射线触发（`scene/penetration.js` 中的 `isPrimary`：hull / turret / gun plates）——与 BlitzKit 的 armor inspector 相同的触发面，其 `shoot()` 只绑定 primary meshes。只穿过 spaced-armor 屏幕或外部模块（tracks、gun barrel）的射线**不会**产生判定，即使该 judgment 本身会对仅含 spaced 层的层栈报告穿透（其 last-layer 规则）；click 路径会在判定前过滤此类层栈，并清除先前的判定，而不是显示过期结果。aim/drag 交互检查（`scripts/browser-armor-aiming.mjs`）用包含屏幕 plate 的 fixture 锁定这一点。炮塔/炮管姿态按 `models.pb` 原点链驱动；固定战斗室车辆（GLB 无 `turret_NN`）的炮管组直接吃 `mG = mT·Rx(gr)`（与 3D 回放同一语义），门禁另用无炮塔 fixture 断言视觉炮管与炮管装甲板的真实矩阵随拖动改变——只读 `#turret-val`/`#gun-val` 会漏掉姿态表未建立的回归。

动能弹（AP/APCR）的层语义遵循 BlitzKit `shoot()`：**每个非外部层都使用该层自身的厚度与命中角，独立应用炮弹 normalization 和 2×-caliber enhanced normalization**；normalization 不会从第一个 plate 继承。外部模块是扁平消耗品，不消耗 normalization，但会递增 hit index，使后续层无法跳弹。`overmatch` 标志只报告实际的 3×-caliber 规则；跳弹只在首个命中层检查（`index > 0` 或 `allowRicochet=false` 会抑制它），click judgment、heatmap 和 ricochet continuation 共享该规则。Enhanced normalization 要求 plate 厚度为正：合法的 0 mm plate 保持 0 mm 有效厚度，而不是除以零（click judgment 与 continuation GLSL/JS 共享该守卫）。Heatmap 累积每层归一化后的有效厚度：`SPACED_FRAG` 写入每个 spaced plate 的 `finalThickness/penetration`，外部模块写入其扁平厚度，而 primary 即使前方有 spaced armor 也应用自身的 normalization（不做 nearest-layer delta correction）。RT1 仍携带最近 plate 的 ricochet/continuation 状态；primary depth mask 阻止 primary 之后的 plate 泄漏状态，且 `SPACED_FRAG` 不再写入 per-plate 的 ricochet gate（后续的陡峭 spaced plate 是有效厚度层，而不是新的首层跳弹）。由于 RT0 是加法式的，primary 在自身层 CDF 之后，对累加的 spaced 有效厚度应用一个聚合 Gaussian CDF（单层 spaced 时精确；多个处于临界值的 spaced 层叠加时为同向近似）；外部模块保持扁平（`RT0.B`）。Heatmap fragment shaders 从 `normalize(vNormal)` 推导命中角。装甲模型会转换为 non-indexed geometry，并在加载时运行 `computeVertexNormals()`，因此每个三角形的三个顶点携带相同的几何面法线——这已与 click judgment 的 `hit.face.normal` 一致。较早的 `dFdx/dFdy(vViewPos)` 导数路径已被移除，因为 shaders 以 `mediump` 运行（许多移动 GPU 上为 fp16），此时逐像素 view-position 导数会量化并产生错乱 heatmap（2026-10-19）。view-space position varying（`vViewPos`）、view direction、angle 和 final thickness 使用 `highp`：在 500 m dolly-zoom 极限下，`mediump` 的 `length(vViewPos)` 可能在分量平方时溢出，即使距离本身可表示，这会把命中角变成 90°/NaN。只有 unit normal 保持 `mediump`。在 8-bit fallback 上，饱和的 `RT0.R` 意味着真实累积覆盖未知，因此按 blocked 处理（fail-closed），而不是读成恰好一次穿透；HE 的 spaced/module 覆盖耗尽名义穿透时仍留在 splash/blocked 分支，绝不进入通用 penetration CDF，而 HEAT（无 splash）只要区间上界仍存在，就仍应用其 gap decay 和 CDF——只有上界耗尽或 8-bit 守卫才强制为 0。Heatmap 概率渐变保持固定的 red→orange→yellow→green scale，使其 low/mid/high 端与结果卡片的 blocked/uncertain/penetration 语义一致；它有意不从主题的 sequential-palette tokens 派生（2026-10-18 用户指令否决了该 review 请求）。HE（canSplash）按 `heatmapMask` 二分：击穿视图画白色遮罩，判据与点击卡片的「击穿」（PENETRATION）逐条同源——① 该像素射线上主装必须是**第一层**（履带/炮管/间隙甲在前时判定链对 HE 首面非主装一律 `penetrated=false`，卡片出 SPLASH/BLOCKED，即被前置层提前挡下，不着白；对应 shader 的 `underSpaced`）；② 等效厚度必须落在穿深浮动区间下端以内（`finalThick <= 0.95×穿深`，卡片概率链 CDF 在 `thickness <= min` 时夹到 100%），区间内的「可能击穿」（1–99%）与区间外（BLOCKED）都不着白；③ 穿深为 0 不亮。溅射伤害渐变（暗红→绿 AI 口径，随点击判定）在**两个视图都保留**，白色只是叠在「可直穿」像素上、盖住该处渐变（白 = 打得穿比该点伤害读数更关键），其余像素照常按 `heDamageNorm` 走 0.18–0.95 alpha 的渐变；未点击时只有白遮罩（它不依赖点击）。默认视图没有白遮罩，叠加层机械由 `syncHeatOverlay` 随「HE 弹种 + 爆点在」建/放，与击穿视图共用同一逐帧管线（2026-10-30 用户裁定）。点击判定的特效（弹道轨迹、命中点标记、HE 溅射半径球）挂在独立 `fxScene`，每个渲染分支末尾再用 `renderFxPass()` 叠一遍：热力图 pass 会 `clearDepth` 后整片着色装甲像素，特效留在主场景会被半透明着色（HE 白色遮罩 alpha≈0.95）盖掉，击穿概率模式下命中点与轨迹会看不清。fxScene 无背景，pass 内临时关闭 `autoClear`；特效材质全是 `MeshBasicMaterial`（不吃光照）。特效之间也用 renderOrder 定序（不随父级继承，必须写在 mesh 上）：溅射球壳 996 → 轨迹 997 → 命中点 999 → 靶环 1000（四者都关闭深度测试），否则球壳会按距离排序盖到轨迹线/层点上。

装甲穿透概率使用 Armor Inspector 机制（`scene/armorInspectorChance.js`）：穿透 roll 范围被当作正态分布的 ±3σ（Blitz ±5% → σ=P/60；PC ±25% 已参数化，但此查看器仅支持 Blitz）。概率路径由截至并包含首个 Primary 的 hits 重建（`penetration.js` 的 `probability_layers`），而不是由确定性的 `layers` 数组重建——后者会在首个未穿透层停止。它有意不包含首个 Primary 之后的远侧 hull/track hits：在 2026-10-18 的一次 Super Conqueror 炮塔点击中，那些隐藏层让两个相邻位置分别显示 19% 与 0%，而确定性判定与 heatmap 都认为穿透（约 71%）；在首个 Primary 停止后恢复了一致。每个实际装甲层都会计算 Gaussian CDF，然后将区间**两端**平移**一个**有效厚度，因此 σ 保持在 segment 起始值；外部模块是扁平平移（不是 CDF 层），区间耗尽时结果为 0；跳弹不参与概率计算。continuation segment 在其首个 `seg=1` 层初始化一次，并在该 segment 的其余部分保持累积区间。2026-10-18 的 Super Conqueror 回归修正了此前对 wasm 缩放的误读：252 AP 对 20mm spaced（2×-caliber normalization 后为 21.5mm）+ 155mm primary（自身 5° normalization 后在 42° 为 194.1mm）合计 215.6mm，剩余 36.4mm，确定性判定为穿透；该概率模型与确定性 `penetration.js`（BlitzKit port）使用相同的 **1×、按层归一化** 有效厚度。对于 AP/APCR/HEAT，卡片现在使用完整概率链作为其单一层链：每个层点使用累积概率（0% 红、1–99% 黄、100% 绿），标题根据总体概率显示 BLOCKED / “May penetrate p%” / PENETRATION，任何非零概率都会显示炮弹的完整伤害，即使确定性均值被 blocked（<1% 显示为 `<1%`，不会舍入为 0；从 99.5% 到但不含 100% 的部分概率显示为 `>99%`，绝不为 `100%`）。如果累积概率在首个 Primary 之前就达到 0，该链仍会完整输出，剩余层概率为 0，因此卡片行、点和轨迹终点不会消失。只有当 HE 的首个表面是 Primary 时，它才遵循同一概率卡片：HE 在该处有穿透 roll，因此标题/层点/伤害使用概率链（任何非零概率都显示完整 HE 伤害）。如果首个表面是非 Primary 的 spaced/module（HE 不会穿透它），或穿透概率为 0，则保留确定性的首表面 SPLASH/BLOCKED 分支。概率模式还要求 Primary 具有正厚度（`penetration.js` 的 `hasPositivePrimary`）：终止于外部模块（track/gun barrel）或 0 mm plate 的射线保持确定性，因此模块的扁平消耗不会被误读为必定穿透并造成完整伤害。Ricochet/continuation 保留确定性分支；确定性结果仍是这些特殊路径的名义上的最终判定/伤害权威，并为概率链提供 geometry engine。概率层收集会丢弃同一 plate 的重合 hits（射线穿过 quad 对角线时会在同一点报告两个三角形），以免同一物理层被计算两次；同一 plate 的非重合重复会按出现次数匹配到轨迹点（`matchHitsByOccurrence`），而不是按第一个 part-name 匹配。primary heatmap shader（`tankViewer.js` 的 `aiNormalCdf`）消费相同的 1× 有效厚度（RT0.R 是逐层归一化有效厚度之和加上 module 扁平消耗）和区间宽度；ricochet-continuation 的 GLSL/JS（`armorCollisionPack.js`）传播相同的 1× 区间，并像 click 链一样在首个 Primary 停止（补充概率为零时保持确定性绿色）；名义 continuation block 的补充概率为 1–99% 时，会编码为该概率带，而不是直接显示为红色，以匹配卡片的 “May penetrate p%” 标题（0%/100% 仍为确定性红色）；这包括在首个 Primary **之前**的 spaced/module 层发生 block（GPU/JS 仍会累积穿过该 Primary 的概率，例如剩余 100mm 时 spaced100→hull1 两者都约为 13.7%）。固定的 `#traj-info` 卡片根据 canvas `getBoundingClientRect()` 定位，并被夹取到可见 canvas 内；`browser-armor-aiming` 会滚动真实布局 fixture，并断言卡片垂直偏移跟随 canvas，因为 source-regex 守卫无法证明定位路径真的执行。HE splash 伤害采用 Armor Inspector func7695 的 800 射线采样（`scene/heSplash.js`）：爆点沿射向反方向外移 0.1m，固定 20×40 世界方向，名义层厚累加到首个 Primary（含），`he_min/he_max` 是两个伤害 roll 界各自的最大值。采样结果有三态：`samples>0` 正常；`samples===0` 是**权威零伤害**（爆炸半径内没有任何射线遇到主装，func7695 跳过这类样本，卡片显示 BLOCKED）；碰撞包/网格/入参导致采样器无法运行时判定返回 ERROR，卡片显示「溅射采样不可用 + reason」，**不回退单射线公式**。只有从未提供采样器的上游/纯函数调用方（`/api/penetrate` 契约）沿用单射线 func7695 公式，结果标记 `source:'single-ray', degraded:true`。旧的 BlitzKit `1.1×effective` 溅射公式已退役。普通装甲检视里**切换弹种、换射手主炮、切换目标配置或校准弹/强化装甲都只清除上一次判定结果**（结果卡/轨迹/命中标记/HE 爆点），不按旧点击位置重跑；射击复现的装备/目标配置重判沿录像 `launch/lvDir` 权威射线，不用相机中心射线替代；新弹种需要重新点击才产生结果（射击复现与世界 tick 的换弹仍按权威弹道重算）。`#traj-info` 结果卡在**窄屏竖屏手机（<768px 且高>宽）与矮视口 / 横屏手机（高 < 520px）**下使用紧凑尺寸（`utils/shotResultCardMetrics.js`：padding、标题/概率/层行字号与行高、层间距均缩小；桌面数值不变），且紧凑档最大宽度封顶 420px（随画布宽度进一步收窄），避免 fixed overlay 在横屏里铺满整屏；宽度口径由 `shotResultCardMaxWidth` 统一，渲染与 resize 刷新共用。

**已知 heatmap 近似（2026-10-18，用户已接受）。** click 卡片使用前缀平移后的区间逐层相乘 CDF：`∏ Φ((P - M - S_i)/σ) × Φ((P - M - A - T)/σ)`，其中 `S_i` 是第 i 层之前的 spaced/module 累积厚度。RT0 无法复现该乘积：加法混合只存储 `Σ spaced effective`（`R`）、module flat（`B`），在半浮点路径中还存储 spaced 层数（`G`）；每层的 CDF 依赖**有序前缀和**，单 pass 的 fragment 无法读取它（同一 target 的 feedback；核心 WebGL2 没有可移植的 framebuffer fetch），而总和/计数无法重建顺序。具体而言，`P=100`、spaced 99 mm + 1 mm + primary 0.5 mm 在顺序 99→1→0.5 下为 13.9%，在顺序 1→99→0.5 下为 19.1%，而 RT0 存储的 `A=100` 相同。因此 primary shader 在 `A` 处乘以一个聚合 spaced CDF；它对零个或一个 spaced 层是**精确的**，包括完全位于该层前方的外部模块（RT1 的 `moduleInFront` 用 `moduleFlat` 平移 spaced CDF 基数；基数保留符号而不是在 0 处截断，因此比穿透更厚的模块仍保留正尾部——P199/chassis200/spaced1/hull1 在两者中都是 5.0%）。对于两个或更多 spaced 层，以及 spaced 层栈两侧都有模块的情况（RT0 只存储 module flat 总量），它只是近似，当较早的 spaced 层本身处于临界状态时会偏离。HEAT 的层间 gap 衰减有同样限制：`spacedArmorDepth` 只存储最近的覆盖深度，因此 shader 应用一个总距离因子 `1−0.5·Σd`；卡片乘的是 `∏(1−0.5·d_i)`，在多个 gap 时严格更小。结果卡片是权威来源；精确的 per-gap 衰减需要上文推迟的同一有序逐层深度 trace/peeling。精确替代方案是条件式 packed-grid per-pixel trace 或 depth peeling，因移动端成本而推迟；click 卡片/`penetrationChance()` 仍是权威来源，`?armordebug=1` 会暴露两条链以供比较。

Auth 状态只有一个所有者：`useAuth()` singleton refs（`authenticated` / `tokenParsed` / `authInitState`）。每个消费者都从这些 refs（或 `computed` 派生值）渲染，因此登录返回、Android `authChanged` push 或登出都会翻转整个 SPA，无需 reload 或 remount。`initPromise` *仅*是 bootstrap 完成结算的信号，不携带 session 真实状态（它 resolve 为 `undefined`）：它是模块级的一次性 init transaction，`logout()` 只会重新投影 refs——绝不重建该 transaction，因此从中读出的任何值都是首次 init 的过期快照。重新挂载的页面必须 await 它，然后基于 `isAuthenticated()` / `authenticated` 分支，绝不能基于 promise 的值。登出是 local-first：refs 在任何网络调用之前清空，浏览器 end-session 仅尽力而为（仅在连接状态*已知*离线时跳过——`unknown` 仍会尝试，unknown 不等于 offline），落地目标为 runtime 默认值（公开生产 Web → Home；Android APK 和本地 Web → Replay），绝不是登出前的 view。刷新被拒绝本身不是登出：浏览器会扣留其 API token，并保留投影身份以便稍后重试，包括在线时。Android 会重新读取 Native 状态；瞬时失败保留其 cache，而永久性 Native token 拒绝可清除该 session。Reload/check-sso 与显式登出仍是权威。生命周期长于一次 UI turn 的业务请求（profile / records / hundred status）携带发起时捕获的 `authEpoch()`，并必须在发布前重新检查所有权——A 账户的迟到响应绝不能落在切换到 B 之后。

`app/viewRegistry.js` 是唯一的 view → capability 映射：`replay` → `data`、`battle-playback` → `playback`、`agent-replay` → `3d`、`agent-shots` → `shots`、`ai-review` → `ai`。全部五个能力都在公开界面可发现。Data 与 2D Playback 可匿名使用。个人回放在 3D Playback 与 Shot Analysis / Reconstruction 中要求认证；已验证的官方示例文件同样允许匿名访问这两个能力。AI Review 始终要求认证，包括使用 demo 时。`wotbtools-admin` 不会改变 Replay Workspace 的能力。

Battle Playback 遵循相同的呈现边界：`BattlePlayback.vue` 仍是 orchestration root，而 `BattlePlaybackHud.vue`、`BattleMap.vue`、`PlaybackControls.vue`、`PlaybackTransport.vue`、`PlaybackTimeline.vue`、`PlaybackDisplaySurface.vue`、`AnnotationToolbar.vue` 和 `VehicleDetailsPanel.vue` 分别拥有 HUD、地图、控件、共享 primary composition、timeline、Gear-anchored Display surface、annotation 和选中载具呈现。`PlaybackMobileOverlay.vue` 只拥有临时移动端控件可见性。纯 playback 投影与 clock helpers 位于 `utils/playbackVehicleState.ts` 和 `utils/playbackClock.ts`；规范 V2 query 语义与 tank-marker assets 保持不变。
持久化的 Playback 呈现状态在 `composables/usePlaybackPreferences.ts` 中有一个模块级响应式所有者：player/tank 标签、battlefield-label reload 开关、HP HUD 可见性、recent trails 以及 battlefield-UI block 开关（`uiPrefs`：top bar / roster / kill feed / base status）保留各自的历史 storage keys、默认值与迁移行为。rail pane-width 与 rail-collapse 偏好已随其所属的 rail/drawer/Details-column 模型一并移除；其过时的 storage keys 不再被读取或重写。每个活跃消费者收到相同对象；kept-alive 的 2D 与 3D panes 中的变更彼此立即可见，持久化无法写入过期的独立副本。两个 root 都保持 domain projection/rendering 独立于 persistence policy。

`PlaybackVehicleLabel.vue` 在两条路径上拥有 player/tank 名称、HP 数字/百分比/视觉、reload segments 以及 destroyed/last-known 呈现。`PlaybackSidePanel.vue` 不再被任一 renderer 挂载：它服务的 rail / drawer / Details-column 模型已被 Gear-anchored Display surface 加上可拖拽的 `VehicleDetailsPanel` 取代；它仅作为带自身测试的独立组件保留。`VehicleMarker.vue` 提供地图定位的 2D 状态与碰撞放置；`PlaybackVehicleLabels3D.vue` 提供屏幕定位的 3D anchors。场景通过相机投影载具世界坐标，并仅通过隔离的命令式桥接在渲染速度下更新 anchor DOM transforms/visibility。标签内容以 HUD 节奏（约 10Hz）发布给专用子组件，seek 时立即更新；`Replay3DPane` 的响应式树不会以原始渲染 FPS 更新。相机后方、屏幕外和不可见的载具会被隐藏，保留现有遮挡语义，HTML overlay 不会拦截场景 pointer 输入。载具标签没有 CanvasTexture/Sprite renderer；浮动伤害 sprites 仍是独立的 Three.js 反馈。

Reload 解释由 `scene/reloadBar.js#createReloadStateResolver` 拥有：两个 panes 查询相同的纯 state-at-time 语义。`parseLocalPlayback` 在规范 2D dataset 旁携带权威 Playback reload telemetry，而不是将其加入通用 `ReplayFacts`。无 telemetry、unknown relation 和 enemy relation 都不产生 reload 呈现；pause/seek 绝不会累积独立的倒计时。

3D Hide All UI 是临时的 pane 状态。其唯一的 `setUiHidden()` transition 在进入时关闭 Display，并同时门控 HUD、roster、kill feed、bases、labels、controls、display panel 和 result banner；只保留恢复入口。按钮与 H 快捷键使用该 transition，交互式键盘目标被排除在外。

Playback phone form 由两个 renderers 通过 `usePlaybackPhoneForm()` 和 `PLAYBACK_MOBILE_QUERY` 共享。Vue 渲染与 3D `.phone-form` root class 使用这一语义判断；仅基于宽度的 CSS 无法把 844×390 粗指针手机变成 tablet 布局。紧凑 speed/transport、次级 controls 与 safe areas 遵循同一 phone form；portrait-flow 与 landscape side lanes 是另一个由 `usePlaybackPortraitViewport()` 共享的判断。具有 tablet 高度 viewports 的触屏平板保持 tablet 呈现。`usePlaybackFullscreen()` 用 `document.fullscreenElement === target()` 跟踪所有权；并发挂载的 panes 绝不会报告另一个 target 的 fullscreen。只有手机进入自己的 fullscreen 时才尝试横屏方向。

Roster 呈现只有一个响应式契约。非竖屏布局，包括手机横屏/fullscreen 和短 viewports，保持常驻 side lanes，recorder allies 在左、enemies 在右；正常 7v7 行无需 team/lane scrollbars 即可容纳。竖屏布局使用自然文档流：HUD / 方形 Stage / Transport / Display（打开时）/ inline Details / allies / enemies，页面滚动，而不是分别滚动 team boxes。不存在按需出现的临时 roster 表面。`uiPrefs.showRoster` 只移除 roster 呈现；data、selection、follow target、camera 和 playback 保持不变。当 lanes 隐藏时，renderer 仍保持其 Stage 契约：2D 保持方形，而 3D 在横屏时填满可用中心、在竖屏时保持方形。

`Replay3DPane` 拥有选中载具状态。Three.js raycast 通过 scene callback 报告选择意图；它从不拥有 Vue selection。Scene selection 打开共享的 `VehicleDetailsPanel.vue`；点击 3D roster-row 会显式跟随该载具。Follow 是显式 camera command，Free/Top 会保留 selection。Details panel 接受通用 identity/HP/time，以及可选的 portrait、last-known/destruction time、stats、track inspector 和 damage log；2D 与 3D 使用 workspace 拥有的规范 dataset 提供这些证据。3D 从 scene identity/HP 状态开始，并在规范数据到达时增强已打开的 panel；不可用的 sections 会被省略，规范数据失败不会阻塞场景。同一个 Details 组件在非竖屏布局（包括手机横屏/短 viewports）中可拖拽并浮动于 workspace，在竖屏中则 inline 位于 Transport/Display 之后。Details 可见性不会重置/重新解析 playback，也不会重新加载 assets。

物理队伍身份与 recorder 视角呈现保持区分。2D 与 3D 的 roster lanes 都通过 `scene/rosterState.js#rosterLanesFor` 将 recorder allies 放在左侧、enemies 放在右侧；未知玩家仍是独立分组。`PlaybackRoster` 接收 `friendlyTeam` 并派生 friendly/enemy 标题以及 `--color-team-ally` / `--color-team-enemy` 颜色。物理 `team1` / `team2` keys 在数据中保持不变；在 recorder team 未知时，lane 排序回退为 Team 1 左 / Team 2 右，行颜色保持中性。`scene/rosterState.js` 拥有 roster 的 state-at-time 投影（identity rows 只构建一次，`hp` / `dead` 按 `t` 重新投影）；label 呈现使用共享 Vue 组件和语义 CSS tokens。

Playback 测试遵循这些所有权边界：map/marker/gesture 契约位于 `BattleMap.test.js`，control 契约位于 `PlaybackControls.test.js`，timeline 契约位于 `PlaybackTimeline.test.js`，HUD/mobile/panel 契约位于各自聚焦的组件测试套件，detail-panel 契约位于 `VehicleDetailsPanel.test.js`，纯 projection/clock 契约位于 `utils/playbackVehicleState.test.js` / `utils/playbackClock.test.js`。共享 playback fixtures 位于仅用于测试的 `playbackTestHarness.js`。`BattlePlayback.test.js` 与其余 `BattlePlayback.integration.test.js` 用例保留给跨组件/领域回归；呈现用例不在那里重复。

源码级 CSS 守卫对所有权不变量仍然有用，但最终布局行为不能从 CSS 文本推断。`pnpm run test:browser-layout` 会启动 CI runner 上可用的 Chrome/Chromium，加载真实的 shared/PC/tablet/mobile Playback stylesheets，并检查 1600×900 PC、1024×768 tablet、390×844 mobile 的真实 computed styles / geometry，外加一个跨形态隔离用例。该检查在 frontend CI 中先于生产构建运行。CSS 文本也无法体现*交互*真相，因此 `pnpm run test:browser-interaction` 覆盖另一半：它加载真实应用（router / AppShell / ReplayWorkspace / 每个 stylesheet，仅 stub 掉 Keycloak 边界），模拟 device metrics 与粗指针，驱动**真实输入管线**（原始 touch / mouse 事件，绝不用合成的 `click()`），并通过页面内事件记录证明真实点击目标**就是**预期控件。它覆盖 375×812 / 390×844 竖屏粗指针、740×360 横屏粗指针、1024×768 tablet、1600×900 desktop、capability switching、未认证登录失败的可见性 + 可重试性、`duration <= 0` 的 transport 不可用，以及竖屏→横屏旋转。其 `roster-geometry-*` 场景还会驱动真实 3D pane：注入 roster/kill-feed fixtures、recorder 视角 lane geometry、行内 HP 数字或回退百分比位于 bar 内且不被截断、display popover 保持在可见 pane 内并避开场景中心、各 block 开关确实移除其 block，以及 hide-all-UI 可恢复。这些 panel 交互使用 `clickElement()`，它将 scroll-into-view、`elementFromPoint` 遮挡检查和 `el.click()` 融合为单次页面内求值——在 fixture 注入的布局仍在稳定时，先从 driver 测坐标再点击是不稳定的，而 hit test 仍针对真实浏览器布局运行（透明 overlay 和遮挡仍会使其失败）。

UI profile 仍然只涉及呈现：`wotb-ui-profile` 是唯一的持久化 key，其派生的 `data-theme` 不会创建独立的 theme 状态。Showcase 与 Classic 必须使用相同的组件、API 与业务状态。

### 第三方 UI 依赖的边界

交互机制由成熟库提供，WotbTools 组件保持自己的 API 与视觉 policy：

- `reka-ui`（headless 交互 primitive）只出现在 `AppDialog`、`AppSheet`、`AppTooltip`、`MenuButton`、`BattlePicker`、`SegmentedControl` 内；`motion-v` 只出现在 `App.vue`（`MotionConfig`）与 `SegmentedControl`、`FilterChips`、`AgentTankopedia` 的过渡中。页面与 feature 不直接 import 它们，由 `src/shared/ui-dependency-ownership.test.ts` 强制。
- `@vueuse/core` 承担浏览器 / Vue 管线（事件监听生命周期、`createReusableTemplate` 等）。breakpoint 只由 `useBreakpoint()` 拥有，带迁移与校验的持久化只由各自 owner 拥有，因此 `useStorage` / `useLocalStorage` / `useSessionStorage` / `useBreakpoints` 被 guard 禁用。
- `motion-v` 的时长与缓动只来自 `src/shared/motion/motionPolicy.ts` 读取的 CSS token；不得在 Vue/JS 中散落 duration 字面量，也不得进入播放帧路径。
- 手机端 overlay 统一使用 `AppSheet`；`DIALOG_INLINE_KEY` 为 true 时 `AppDialog`、`AppSheet`、`MenuButton`、`BattlePicker` 原地渲染（组件测试与 fullscreen 宿主）。

## 架构边界与约束

当前架构边界包含以下各层：

- 应用导航契约是类型化的，且与 feature 解耦；
- AI Review / Map Overview / Battle Playback 的 API 归属只落在 Dataset，panels 不持有 API 归属；
- Replay Workspace 直接消费 auth，并以显式 parent-child replay/workspace props 取代字符串 service-locator 依赖；
- Battle Playback 的高价值持久化归属不在 orchestration root；
- 架构守卫覆盖已移除的 service-locator keys 与 replay capability 的 transport 归属；
- frontend CI 包含真实浏览器 Playback geometry / form-isolation 检查；
- 陈旧的 navigation/auth/replay injection bridges 与重复的 Playback 持久化归属均已不存在。

当前架构不要求纯目录重写，不引入没有明确归属需求的 Pinia，也不把广泛视觉改版或无关产品改动视为架构边界变更的一部分。现有 `?view=` 兼容契约继续保留：删除该兼容层属于产品 URL 迁移，而不是解决上述归属问题的前置条件。

## Android local-first 运行时与能力归属

Android 从 `http://127.0.0.1:21653/index.html` 启动同一个 Vue 应用（自 3.0 起，APK 内置的 GeckoView 运行在 Native LocalRuntimeServer 的 loopback origin 上）；APK 包含其 chunks、commit-addressed Rust/WASM parser、2D assets 和本地 shooting inputs。Native 拥有 lifecycle/update、AppAuth PKCE/token 状态、外部文件入口和连接性；Vue 拥有 routing/product UI/能力门控。Web 保留同源 transport；Android 将服务端拥有的路径——业务 API 与 Android 下载面——解析到 `https://wotbtools.com`，并使用 Native 提供的 Bearer tokens，而 asset-plane 读取（3D assets）仍走本地 `/agent-assets` 路径，由原生 `AgentAssetProxy` 直接转发到对象存储。Sponsor runtime 内容不是 asset-plane 读取：它在构建时从固定的 Release asset 注入并随 bundle 发布，因此 Web 与 APK 各自从自己的 release artifact 同源提供该内容。精确到 origin 的 CORS 由生产网关负责，`deploy/tx/Caddyfile` 中的 Android-Origin 路径列表必须保持同步（`deploy/tx/validate-caddy-config.sh` 断言该精确列表）。内置 frontend 与部署的 Web frontend 是相互独立的 release artifacts。

`ReplayWorkspace` 保留一个 selection/session 所有者以及现有五个 capability/view 映射。LOCAL 的 data/Rating/2D/shooting inspection 在无 Internet 时仍可使用。ONLINE_REQUIRED 的 3D/AI/HoF/Profile 仍可被发现，并在 mount、auth 或 request 之前门控；其原因来自共享 capability 模型，而不是网络超时。断开连接会保留本地状态和缓存的 Native auth；现有 3D session generations 与 AI AbortController 会停止远程工作。重新连接会立即更新可用性，对因连接性受阻的 3D/HoF/Profile 恢复一次，且绝不自动提交 AI。完整矩阵与 snapshot 来源/更新边界见 [`replay-workspace.md`](replay-workspace.md)。

### 推荐目录的接口与部署边界

AppShell 中的 useCreatorAvailability 提供唯一的健康能力与公开分类快照，按 UP/VIDEO 派生类型卡片、列表与总入口可见性。仅 recommendations-v1 启用现行推荐 API，一次公开分类快照包含两个类型的非空分类；仅有作品时总入口也可见。没有该能力时公开及管理入口均不可用，显示可重试提示，不请求旧 UP-only 接口。真实 content-admin 保留技术可用类型的空目录和管理入口；tournament-admin 不拥有内容域，也不显示内容管理入口；完整管理字典不回流公开快照。

RecommendationsPage 是类型入口，CreatorsPage 以 type prop 复用 UP 和作品列表；creators 深链直达 UP，recommended-videos 打开作品，两者属于同一导航栏目。CreatorsConfigPage 用 recommendationType query 选择同一表单/类别管理，VIDEO 不展示实力等级。Vue Router 拥有类型与分类历史，切换前由路由 guard 确认放弃脏草稿/图片；保存中阻止切换。useCreators/useCreatorManagement 将 type 纳入请求所有权，过期 metadata/list/editor 响应不得污染新类型。api/creators.ts 只消费 /api/recommendations 和 /api/admin/recommendations 的现行 wire；等级管理使用后者的 /levels，现行图片引用 /api/creators/avatars/{id} 保留，组件不处理 endpoint 或旧格式适配。

先部署并验证现行后端，再协调网页及内部测试 APK 的接口切换；没有旧接口回退。失败时恢复成对的已验证版本，不回退到无法识别 VIDEO 数据的旧后端。旧内容接口仅内部使用、尚无用户；Native Bridge 保持 v3。Android 最低支持版本门槛由 [Android 发布流程](../android/release-process.md)及 production `version.json` 的当前发布状态拥有，本架构文档不重复固定数值。

初次加载、恢复联网、窗口焦点、显式刷新及管理写入ACK触发共享读取；ACK会作废写前请求。失败保留最近成功快照，不伪造空目录或清掉已保存/正在编辑的草稿。公开分类失效后router.replace回全部，保留其他query/hash；管理员空分类不回退。该状态不替代useFeatureGate的网络判断，不轮询、不保存到localStorage，不承诺跨会话实时更新。
