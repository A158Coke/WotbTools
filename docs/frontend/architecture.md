# Frontend architecture

## Current foundation

Product usage telemetry has one foreground lifecycle owner in `AppShell` (`useUsageTelemetry`). It observes the canonical router view, including workspace capability routes; query-only tank/file/filter changes do not reopen a feature. Replay Data has no page-open event: `useLocalReplayAnalysis` records one start and at most one terminal per selected file, using `parseReplayFiles.onFile` for partial batch completion. Cancellation settles only unfinished files. Only attempt UUIDs, enumerated outcomes and safe error categories leave the client; file names, contents and raw errors stay local.

Signed-in activity is sent on foreground initialization/recovery, authentication becoming ready, and every five minutes while foreground and online. The API transport refreshes the token and rechecks account epoch/foreground ownership before sending; the server validates the bearer and derives account identity. Anonymous feature/parse events use a maximum 100-event memory queue, 20-event batches, and a five-second flush; failed uploads are discarded, without disk persistence or automatic retries. Browser refresh/offline use/process death can lose telemetry. No persistent anonymous identifier or exact anonymous-user count is introduced. Android bundles the same producer; older APKs remain usable without contributing the new events.

新手引导是 AppShell 的单一 `useOnboarding` owner，`OnboardingHost` 消费该 controller；跨层接入只用 shared typed `ONBOARDING_KEY`，Workspace 和各 pane 保留业务状态并注册明确 commands/readiness。指南无独立路由或第二个 replay renderer，见 [功能契约](../features/onboarding.md)。

`main.js` protects a Web OIDC return before importing the router or rewriting the localhost preview URL. When the query or fragment contains `state` together with `code` or `error`, it awaits the existing `useAuth().initPromise` settlement signal; keycloak-js alone validates and consumes the callback. Only then is `createWebHistory` constructed from the adapter's resulting URL and legacy view aliases canonicalized. Successful fragment callbacks are consumed before the router snapshots history. During incoming callback initialization, the provider guards the SDK's public `login` method and enables `onLoad: 'check-sso'` without a silent redirect URI. SDK-valid callbacks bypass `onLoad`; a matching `prompt=none` / `error=login_required` return therefore settles normally as unauthenticated. Missing transactions instead reach the guarded fallback and fail before any new SSO transaction can hide the original failure. SDK-rejected or expired interactive callbacks also require explicit recovery. The original login method is restored when init settles; ordinary visits retain their normal `check-sso` configuration. The provider still uses the SDK's default fragment response mode: recognizing a query-looking URL only delays routing and does not add query-mode support. This presence check never grants authentication. Rejection and the existing 12-second Web watchdog both settle into the existing failed-auth UI; settlement alone does not guarantee every malformed or timed-out URL has been cleaned. Ordinary visits still render while `check-sso` runs; APK startup remains Native-owned and does not wait for this Web callback path. Legacy alias redirects preserve unrelated query values and the hash, including ordinary page anchors.

The application root, [`frontend/src/App.vue`](../../frontend/src/App.vue), only renders Vue Router's outlet. Application concerns live in `frontend/src/app/`:

```text
App.vue
  → app/router.js
  → app/AppShell.vue
      ├── AppSidebar.vue     # 平板 / 桌面（≥ 768）：左侧边栏主导航（含 MorePanel 弹出面板）
      ├── AppTopBar.vue      # compact（< 768）：标题栏
      ├── ViewHost.vue       # <main>，按 ?view= 渲染页面
      ├── AppTabBar.vue      # compact（< 768）：底部主导航
      └── GlobalErrorDialog.vue
```

主导航的唯一数据源是 `app/navigation.js`：`PRIMARY_NAV` 定义首页 · 回放 · 名人堂 · 坦克百科 · 联赛积分榜 · 联赛直播回放 · UP 推荐 · 更多，`primaryNavItems()` 再按 runtime/host 投影实际可见项——public Web home host 保留首页，Android APK 与本地 Web 不显示首页并以回放作为默认落地页；`ADMIN_NAV`（按角色显示的管理入口）与 `primarySection(view)`（视图归属哪个栏目）共享同一导航模型。外壳按 `useBreakpoint()`（`composables/useBreakpoint.js`，断点常量在 `shared/breakpoints.ts`）在两种形态间切换：平板 / 桌面渲染 `AppSidebar`（桌面可折叠，偏好由 `composables/useSidebar.js` 写到 `<html data-sidebar>`，`tokens/scale.css` 据此派生 `--sidebar-w`）；手机渲染 `AppTopBar` 标题栏 + `AppTabBar`。两者都用 `RouterLink` 渲染，并以 `aria-current` 标记当前栏目。直播入口的 `shortLabelKey` 仅用于底部栏和侧栏收起形态，完整名称仍为辅助技术提供；桌面展开形态与页面标题使用完整名称。账户（登录、个人中心、登出）进入 `?view=profile`（`ProfilePage.vue`，未登录时显示说明卡而不是自动跳转）：平板 / 桌面在侧边栏底部，手机在标题栏右侧。"更多"的内容只有一个来源 `composables/useMoreMenu.js`：平板 / 桌面是侧边栏底部的弹出面板（`app/MorePanel.vue`：显示设置 + 关于与支持；管理入口在侧边栏管理组），手机是 `?view=more` 整页（`components/MorePage.vue`，另含按角色显示的管理入口）。

`router.js` owns browser history, deep-link handling, redirects, and Back/Forward. Product URLs deliberately retain the compatible query contract: `?view=replay`, `?view=ai-review`, `?view=battle-playback`, `?view=agent-replay`, and `?view=agent-shots` all resolve to the same kept-alive Replay Workspace with a different initial capability（data / ai / playback / 3d / shots，见 `viewRegistry.js` 的 `replayInitialCapability`）. Legacy aliases (`leaderboard`, `extended`, `reconstruction`) redirect once to their canonical query values. Android also canonicalizes stale landing `?view=home` URLs to the Replay-root URL while preserving unrelated query/hash values; the public Web Home deep link remains valid. `/download/android` and `/download/android/` resolve to the Android page; `/sponsor` is a first-class AppShell route that resolves through `ViewHost` to `SponsorPage`.

**视图私有 query 键**（`navigation.js: locationForView`）：名人堂筛选（tab/page/nation/type/tier/bt/nick/limit）、坦克百科筛选与详情（q/sort/tank/config…）、以及装甲查看器 / 射击复现场景参数（tank/shooter/config/scfg/shell/shot/world/heatmap + 相机与显示档 az/h/d/eqcal/eqenh/quality/move/rel/clean/debug）只属于各自的视图：导航到别的视图时整组丢掉（`locationForView` 三条清理规则），否则从场景切走会在 URL 里留下上一发的 `tank/shot/shooter/…`。留在同一视图内的导航保留全部参数。

3D 回放与射击分析是工作台能力（不再有独立页面）：`agent-replay` / `agent-shots` 深链与工作台 tab 都解析为同一个 kept-alive Replay Workspace 的 `3d` / `shots` pane，与 2D / AI 共用同一条 session（`props.file` 消费工作台已选回放，自身不再有上传入口），并保留工作台上层导航。五个能力永久对所有用户展示，导航不按 admin role 收敛 Agent 深链。3D / shots 在匿名使用个人回放时显示 `ReplayCapabilityAuthGate`；登录或选择已验证的官方示例后才加载 pane；AI 在现有投影边界前门控。`test:browser-interaction` 用真实输入验证普通用户与匿名路径以及 shots → armor 交接。

AI Review is mounted normally: the `?view=ai-review` deep link and workspace tab resolve to the same kept-alive Replay Workspace with the `ai` capability, and that pane mounts `AiReviewWorkspacePane.vue` / `AiReviewPanel.vue` behind the shared auth + local-projection gates (there is no frontend maintenance gate; the `ai_maintenance` locale strings have no consumer). Transport stays in `api/ai-review.ts`; AI inputs are the client canonical projection (`replay-local/ai`), and the backend is the Yecao ai-service (see `docs/operations/ai-service.md`). Replay parsing and Battle Playback remain available through their existing tabs.

`app/viewRegistry.js` is the single source of truth for view names: `VIEW_COMPONENTS` maps supported query views and path-derived views (`android`, `sponsor`) to their components. `app/navigation.js` owns the deep-link contract on top of it, and an unknown view falls back to the default view, so `ALLOWED_VIEWS` must stay equal to the registered view names — `frontend/src/App.test.js` locks that equality. Adding or renaming a view means updating the registry, the allowlist, and its navigation entry points together; a one-sided change silently degrades to the default view instead of failing loudly. Only the landing views (`HomePage`, `ReplayWorkspace`) are imported eagerly; every other view is a `defineAsyncComponent` chunk, and inside the workspace the four capability panes (`BattlePlaybackPanel`, `Replay3DPane`, `ReplayShotsPane`, `AiReviewWorkspacePane`) go through the `defineLazyModule` failure boundary in `utils/lazyModule.ts`, so a stale hashed chunk 404 degrades to a visible, retryable in-pane state instead of unmounting the workspace. Tests that mock these modules must return `__esModule: true` and wait with `vi.dynamicImportSettled()`. `main.js` keeps `<html lang>` and `document.title` (`<section> · WoTBTools`) in sync with the locale and route.

`ViewHost.vue` maps the existing flat page components to a route-derived product view. The flat layout is the current implementation; do not treat another directory layout as already present. Do not add manual `history.pushState`, `replaceState`, or `popstate` listeners to a component; use the injected navigation command, which delegates to Vue Router.

Application navigation is defined by the feature-neutral typed `NAVIGATE_VIEW_KEY` in `frontend/src/shared/navigation.ts`. `AppShell` provides the command; app and feature consumers inject the shared contract without importing router internals or an `app/` implementation module. Production code must not introduce magic-string `inject('navigate')` / `provide('navigate')` calls.

积分赛管理入口由 `useAuth.isTournamentAdmin` 所有（真实 token 中的 `tournament-admin`，全站管理员通过 Keycloak 复合角色继承），不复用全站 `isAdmin` 放大专属角色权限。公开「联赛积分榜」是主导航栏目，位于坦克百科之后；主导航、页面/浏览器标题与导出标题共用 `tournament.title`，公开入口不再重复放到更多面板/页面中。公开积分页持有正式 standings，`utils/tournamentPointsExport.ts` 提供屏幕/Excel/打印文档共享的列投影；管理页的历史导入、预览和幂等提交状态仍归 `useTournamentPointsAdmin` 所有，JSON 文件只在文件边界转为 OpenAPI request，经 `api/tournament-points.ts` 发起请求。

## Dependency and state rules

The required dependency direction is:

```text
app → features → shared
```

The current source tree uses flat `components/`, `composables/`, and `utils/` directories; the dependency rule still applies conceptually without claiming feature folders that do not exist. New work should not create cross-feature private imports or place feature endpoint knowledge in shared code.

Each business state has one authoritative owner. Replay session state (selection, analysis state/results, workspace view state) is owned by `frontend/src/composables/useReplaySession.ts`; the local parse → batch-compute → client-export side effects are driven by `frontend/src/composables/useLocalReplayAnalysis.ts` (over `replay-local/parseReplays.ts` / `replay-local/analyzeReplays.ts`), while `useReplay.ts` exposes that contract as a facade and `useReplayWorkspace.ts` additionally owns the lazy Playback session result shared by 2D, 3D, and Details to the orchestration SFC and capability panels. There is no Processing/Export job state (`useProcessingJob.ts` / `useExportJob.ts` are gone — the server has no replay parser). Derive values with `computed`; use `watch()` for real side effects or lifecycle bridges only, never to synchronize duplicate copies of the same state.

Core Replay/API/AI/Playback contracts live under `frontend/src/types/` and are validated at external JSON/SSE boundaries. JavaScript and TypeScript may coexist during the migration; a `.js` import specifier may resolve to its `.ts` implementation through the Vite/TypeScript resolver, but there must be only one implementation.

Replay HTTP ownership is centralized under `frontend/src/api/`. `replay-capabilities.ts` (name retained as a fossil) owns the shared Bearer/auth-session plumbing (`ReplayAuthSession`, `optionalBearer`, `authedReplayPost`) for the server calls that still exist; `ai-review.ts` owns AI Review SSE/HTTP transport; local parsing, batch compute, export and 2D playback have no HTTP transport (`replay-local/**`), and the locally produced Playback V2 dataset is validated at the boundary by `contract-runtime.ts` (`validateBattlePlaybackDataset`), not fetched. `AiReviewPanel.vue` and `BattlePlaybackPanel.vue` own run/view lifecycle only and must not recreate the `apiFetch` / `authedReplayPost` plumbing or hard-code transport calls.

Replay Workspace presentation is split into focused children (`PageHeader.vue`, `ReplayCapabilityTabs.vue`, `FileDrop.vue` — the single site-wide file surface — and `BattlePicker.vue` for the single-battle capabilities; status and gates use `EmptyState.vue` / `Banner.vue`). One workplace hosts all five capabilities (`data` / `playback` / `3d` / `shots` / `ai`): `ReplayWorkspace.vue` is the only capability orchestrator and lazy-mounts `BattlePlaybackPanel.vue`, `Replay3DPane.vue`, `ReplayShotsPane.vue` and `AiReviewWorkspacePane.vue` on first activation (`composables/useMountedWhenActive.js`), keeping each pane's session alive when the capability is switched away. The three single-battle panes and the 3D pane share one `file` / `active` / `blockedReason` prop contract; none of them owns a file picker or a second session. The Data result toolbar inside `ReplayPage.vue` uses `SegmentedControl.vue`, `BattlePicker.vue` and `MenuButton.vue`; `SeriesOverview.vue` renders the series score derived by `utils/replaySeries.js`. Selection / analysis state / current battle remain owned by `useReplayWorkspace()` / the Replay session (local parse + batch compute side effects run through `useLocalReplayAnalysis`). Direct parent-child dependencies are explicit: `ReplayWorkspace.vue` passes the authoritative replay session and workspace presentation state to `ReplayPage.vue` as props instead of hiding them behind `provide('replay')` / `provide('replayWorkspace')`. Authentication is consumed from the existing `useAuth()` singleton rather than re-exported by `AppShell` through string service-locator keys.

The armor viewer (`agent-armor`) is available anonymously; personal replay shots remain gated in the Replay Workspace, while verified official-demo shots are also available anonymously. Browser login preserves the complete scene query; ordinary signed-in users can consume shot reconstruction without an admin role. It stays a separate page: it belongs to the Tankopedia side and keeps its own URL contract (`?tank= &shooter= &config= &shell= &shot= &world=1`). The Replay workplace reuses its *engine* (penetration math, tank assets, `scene/tankViewer.js` marker palette), not its page navigation model — the shot inspector hands the shot data over through the existing local handoff channel and asks the router to open that destination.

Armor thickness is **configuration-scoped**: the viewer reads `configs[].turret_plates`, `configs[].gun_plates` and `configs[].gun_thickness` from the selected `tank/{id}.json` config. `armor_model` remains only a top-config summary and is not a fallback source; a missing per-config plate fails closed to 0 mm. On a config change the viewer refreshes the armor-plate cache, the visual gun-barrel module cache, spaced classification, and the current collision material colors; the heatmap rebuild and click judgment then read those refreshed caches. `armor_model` must not be restored as a fallback without a new asset-shape contract.

Engagement distance for the penetration falloff (`penetration_far`, client 0x719740) is mode-dependent: **shot replay uses the server-decoded ballistic path length** (`shotBallisticLength` in `scene/agentData.js`: `ball_a → via… → ball_b` polyline total, ricochet legs included — the distance the shell actually flew), while **static armor inspection uses the camera → first-hit-plate distance**. Both feed the same judgment and the penetration-map uniforms; the result card shows the value used. Camera-click judgments in the armor viewer fire only for rays that reach **main armor** (`isPrimary` in `scene/penetration.js`: hull / turret / gun plates) — the same trigger surface as BlitzKit's armor inspector, whose `shoot()` is bound to primary meshes only. A ray that crosses nothing but spaced-armor screens or external modules (tracks, gun barrel) does **not** produce a verdict, even though the judgment itself would report penetration for a spaced-only layer stack (its last-layer rule); the click path filters such stacks before judging and clears the previous verdict instead of showing a stale one. The aim/drag interaction gate (`scripts/browser-armor-aiming.mjs`) locks this with a fixture screen plate.

Kinetic (AP/APCR) layer semantics follow BlitzKit `shoot()`: **every non-external layer independently applies shell normalization and the 2×-caliber enhanced normalization using that layer's own thickness and impact angle**; normalization is not inherited from the first plate. External modules are flat consumables and do not consume normalization, but they increment the hit index so later layers cannot ricochet. The `overmatch` flag reports only the actual 3×-caliber rule; ricochet is only checked on the first hit layer (`index > 0` or `allowRicochet=false` suppresses it), and the click judgment, heatmap and ricochet continuation share that rule. Enhanced normalization requires a positive plate thickness: a legal 0 mm plate stays at 0 mm effective instead of dividing by zero (the click judgment and the continuation GLSL/JS share the guard). The heatmap accumulates per-layer normalized effective thickness: `SPACED_FRAG` writes each spaced plate's `finalThickness/penetration`, external modules write their flat thickness, and the primary applies its own normalization even when spaced armor is in front (no nearest-layer delta correction). RT1 still carries the nearest plate's ricochet/continuation state; the primary depth mask prevents plates behind the primary from leaking state, and `SPACED_FRAG` no longer writes a per-plate ricochet gate (a later steep spaced plate is an effective-thickness layer, not a fresh first-layer ricochet). Because RT0 is additive, the primary applies one aggregate Gaussian CDF for the summed spaced effective thickness (exact for one spaced layer; same-direction approximation when several marginal spaced layers stack) after its own layer CDF; external modules remain flat (`RT0.B`). The heatmap fragment shaders derive the impact angle from the **geometric face normal** (`dFdx/dFdy` of the view position), matching the click judgment's `hit.face.normal`; interpolated GLB vertex normals are not used for the judgment color, because smooth normals on faceted plates made the heatmap red where the card said penetration. On the 8-bit fallback, a saturated `RT0.R` means the real accumulated coverage is unknown, so it is treated as blocked (fail-closed) instead of being read as exactly one penetration; HE whose spaced/module coverage exhausts the nominal penetration stays in the splash/blocked branch and never enters the generic penetration CDF, while HEAT (no splash) still applies its gap decay and CDF as long as the interval upper bound survives — only the upper-bound exhaustion or the 8-bit guard forces 0. The heatmap probability ramp stays the fixed red→orange→yellow→green scale so its low/mid/high ends match the result card's blocked/uncertain/penetration semantics; it is intentionally not derived from the theme's sequential-palette tokens (2026-10-18 user directive rejecting that review request).

Armor-penetration probability uses the Armor Inspector mechanism (`scene/armorInspectorChance.js`): the penetration roll range is treated as a normal distribution's ±3σ (Blitz ±5% → σ=P/60; PC ±25% is parameterized but this viewer is Blitz-only). The probability path is rebuilt from the hits up to and including the first Primary (`penetration.js` `probability_layers`), not from the deterministic `layers` array, which stops at the first non-penetrating layer. It deliberately does not include far-side hull/track hits after the first Primary: on a 2026-10-18 Super Conqueror turret click those hidden layers made two adjacent positions read 19% vs 0% while the deterministic verdict and heatmap both said penetration (~71%); stopping at the first Primary restored agreement. Each actual armor layer evaluates the Gaussian CDF and then translates **both** interval bounds by **one** effective thickness, so σ stays at the segment-start value; external modules are flat translations (not CDF layers) and exhausting the interval yields 0; ricochets are not probabilistic. A continuation segment initializes once at its first `seg=1` layer and keeps the accumulated interval across the rest of that segment. The 2026-10-18 Super Conqueror regression fixed the earlier misread of the wasm scaling: 252 AP vs 20mm spaced (21.5mm after 2×-caliber normalization) + 155mm primary (194.1mm at 42° after its own 5° normalization) totals 215.6mm, leaving 36.4mm and a deterministic penetration; both this probability model and the deterministic `penetration.js` (BlitzKit port) use the same **1×, per-layer-normalized** effective thickness. The card prints the probability only when it is 1–99%; 0/100 trivially follows the deterministic verdict, and HE never converts a SPLASH/BLOCKED terminal state into “may penetrate”. The probability layer collection drops coincident hits of the same plate (a ray crossing the diagonal of a quad reports two triangles at the same point) so one physical layer is not counted twice. The primary heatmap shader (`tankViewer.js` `aiNormalCdf`) consumes the same 1× effective thickness (RT0.R is the sum of per-layer normalized effective thickness plus module flat consumption) and the interval width; the ricochet-continuation GLSL/JS (`armorCollisionPack.js`) propagates the same 1× interval and stops at the first Primary like the click chain (a zero supplemental probability keeps the deterministic green); a nominal continuation block whose supplemental probability is 1–99% is encoded as that probability band instead of hard red, matching the card's “May penetrate p%” title (0%/100% stays the deterministic red); this includes a block at a spaced/module layer **before** the first Primary (the GPU/JS still accumulate probability through that Primary, e.g. spaced100→hull1 at 100mm remaining is ~13.7% in both). The fixed `#traj-info` card is positioned from the canvas `getBoundingClientRect()` and clamped into the visible canvas; `browser-armor-aiming` scrolls a real layout fixture and asserts the card's vertical delta follows the canvas, because a source-regex guard cannot prove the positioning path actually runs.

**Known heatmap approximation (2026-10-18, user-accepted).** The click card multiplies per-layer CDFs with prefix-shifted intervals: `∏ Φ((P - M - S_i)/σ) × Φ((P - M - A - T)/σ)`, where `S_i` is the cumulative spaced/module thickness before layer i. RT0 cannot reproduce that product: additive blending stores only `Σ spaced effective` (`R`), module flat (`B`) and, in the half-float path, the spaced layer count (`G`); each layer's CDF depends on the **ordered prefix sum**, which a single-pass fragment cannot read (same-target feedback; core WebGL2 has no portable framebuffer fetch), and sum/count cannot reconstruct the order. Concretely, `P=100` with spaced 99 mm + 1 mm + primary 0.5 mm gives 13.9% in order 99→1→0.5 but 19.1% in order 1→99→0.5, while RT0 stores the same `A=100`. The primary shader therefore multiplies one aggregate spaced CDF at `A`; it is **exact for zero or one spaced layer**, including an external module entirely in front of that layer (RT1 `moduleInFront` shifts the spaced CDF base by `moduleFlat`; the base keeps its sign rather than clamping at 0, so a module thicker than penetration still keeps the positive tail — P199/chassis200/spaced1/hull1 is 5.0% in both). It is an approximation for two or more spaced layers, and for modules on both sides of a spaced stack (RT0 only stores the total module flat), diverging when an early spaced layer is itself marginal. HEAT's inter-layer gap decay has the same limitation: `spacedArmorDepth` stores only the nearest coverage depth, so the shader applies one total-distance factor `1−0.5·Σd`; the card multiplies `∏(1−0.5·d_i)`, which is strictly smaller for multiple gaps. The card is authoritative; exact per-gap decay requires the same ordered per-layer depth trace/peeling deferred above. Exact alternatives are a conditional packed-grid per-pixel trace or depth peeling, deferred because of mobile cost; the click card/`penetrationChance()` remains authoritative, and `?armordebug=1` exposes both chains for comparison.

The single-tank armor camera and single-tank shot replay use the measured Armor Inspector FOV calibration: 15 m / 18.75° reference, 40° maximum FOV, 0.5° minimum FOV as a far fallback; below 15 m the FOV widens so the hull keeps its 15 m screen size, while the FOV product (`tan(fov/2)×d`) rises from ≈2.477 at 15 m by +0.0128/m to a 2.8 cap — matching Armor Inspector's measured 2.37→2.65 drift and making the tank slightly smaller at range (~12% smaller at the cap) instead of perfectly constant. `near=0.05d`, `far=d+30`. The default camera faces the tank head-on (-Z) and level, aiming at the armor model bounding-box center at a 15 m distance (falling back to the gun line if the box is empty), so the tank is vertically centered at the 18.75° reference framing; camera presets use their own `ty` (gun line or top-view height) as the target height. The measured 6.5–30 m is the FOV calibration reference, not a hard zoom clamp. The two-tank world overview stays at the native 50° framing. A recorded **hit** shot opens in the impact view (15 m / 18.75°, impact button pressed) and the “Overview” toggle restores 50°; a **miss** has no impact point and opens in the world overview at 50° with the impact button disabled. Camera presets use `?camview=front|top|...`; the SPA route key `view=agent-armor` is never treated as a camera preset, so it cannot override the default 15 m framing.

The armor viewer's tank selector and the Tankopedia list are one menu implementation (`components/TankCatalogMenu.vue`) over one roster view model (`normalizeTankCache` + `selectTanks`): fuzzy search with search aliases, tier/nation/type filters, name/tier/hp/pen sort, compact chips + filter sheet, incremental cards, and loading/empty/error states are identical. `AgentTankopedia` keeps URL state and the detail view only; `AgentArmorView` keeps the dialog shell and forwards the viewer callbacks (`onTankList`, `onTankSelection`, `selectTank`). A roster change or a changed search/filter contract must land in the shared component, not in either page.

Auth state has exactly one owner: the `useAuth()` singleton refs (`authenticated` / `tokenParsed` / `authInitState`). Every consumer renders from those refs (or `computed` derivations), so a login return, an Android `authChanged` push or a logout flips the whole SPA without a reload or remount. `initPromise` is *only* a bootstrap-settled signal and carries no session truth (it resolves `undefined`): it is the module-level one-shot init transaction, and `logout()` only re-projects the refs — it never rebuilds that transaction, so any value read out of it is a stale snapshot from the first init. A remounting page must await it and then branch on `isAuthenticated()` / `authenticated`, never on the promise's value. Logout is local-first: refs are cleared before any network call, the browser end-session is best effort (skipped only when connectivity is *known* offline — `unknown` still attempts, unknown ≠ offline), and the landing destination is the runtime default (public production Web → Home; Android APK and local Web → Replay), never the pre-logout view. A refresh rejection is not itself logout: the browser withholds its API token and preserves the projected identity for a later retry, including while online. Android re-reads Native state; transient failures preserve its cache, while a permanent Native token rejection can clear that session. Reload/check-sso and explicit logout remain authoritative. Business requests that outlive a UI turn (profile / records / hundred status) carry the `authEpoch()` captured at issue time and must re-check ownership before publishing — a late A-account response must never land after the switch to B.

`app/viewRegistry.js` is the single view → capability map: `replay` → `data`, `battle-playback` → `playback`, `agent-replay` → `3d`, `agent-shots` → `shots`, `ai-review` → `ai`. All five capabilities are publicly discoverable. Data and 2D Playback are usable anonymously. Personal replays require authentication for 3D Playback and Shot Analysis / Reconstruction; verified official-demo files also permit anonymous access to those two capabilities. AI Review always requires authentication, including for the demo. `wotbtools-admin` does not alter Replay Workspace capabilities.

Battle Playback follows the same presentation boundary: `BattlePlayback.vue` remains the orchestration root, while `BattlePlaybackHud.vue`, `BattleMap.vue`, `PlaybackControls.vue`, `PlaybackTransport.vue`, `PlaybackTimeline.vue`, `PlaybackDisplaySurface.vue`, `AnnotationToolbar.vue`, and `VehicleDetailsPanel.vue` own HUD, map, controls, the shared primary composition, timeline, the Gear-anchored Display surface, annotation, and selected-vehicle presentation respectively. `PlaybackMobileOverlay.vue` owns only transient mobile controls visibility. Pure playback projection and clock helpers live in `utils/playbackVehicleState.ts` and `utils/playbackClock.ts`; canonical V2 query semantics and tank-marker assets remain unchanged.
Persisted Playback presentation state has one module-level reactive owner in `composables/usePlaybackPreferences.ts`: player/tank labels, the battlefield-label reload toggle, HP HUD visibility, recent trails and the battlefield-UI block toggles (`uiPrefs`: top bar / roster / kill feed / base status) retain their historical storage keys/defaults and migration behavior. The rail pane-width and rail-collapse preferences were removed together with the rail/drawer/Details-column models they belonged to; their stale storage keys are no longer read or rewritten. Every live consumer receives the same objects; changes in the kept-alive 2D and 3D panes are immediately visible to each other, and persistence cannot write a stale independent copy. Both roots keep domain projection/rendering independent from persistence policy.

`PlaybackVehicleLabel.vue` owns player/tank names, HP number/percentage/visual, reload segments, and destroyed/last-known presentation for both paths. `PlaybackSidePanel.vue` is no longer mounted by either renderer: the rail / drawer / Details-column models it served were replaced by the Gear-anchored Display surface plus the draggable `VehicleDetailsPanel`; it survives only as a standalone component with its own test. `VehicleMarker.vue` supplies map-positioned 2D state and collision placement; `PlaybackVehicleLabels3D.vue` supplies screen-positioned 3D anchors. The scene projects vehicle world positions through the camera and updates only anchor DOM transforms/visibility through an isolated imperative bridge at render speed. Label content is published to the dedicated child at the HUD cadence (~10Hz), with immediate seek updates; the `Replay3DPane` reactive tree does not update at raw render FPS. Behind-camera, offscreen and nonvisible vehicles are hidden, existing occlusion semantics are retained, and the HTML overlay does not intercept scene pointer input. Vehicle labels have no CanvasTexture/Sprite renderer; floating damage sprites remain independent Three.js feedback.

Reload interpretation is owned by `scene/reloadBar.js#createReloadStateResolver`: both panes query the same pure state-at-time semantics. `parseLocalPlayback` carries authoritative Playback reload telemetry alongside the canonical 2D dataset, rather than adding it to generic `ReplayFacts`. No telemetry, unknown relation and enemy relation yield no reload presentation; pause/seek never integrate an independent countdown.

3D Hide All UI is transient pane state. Its single `setUiHidden()` transition closes Display on entry and gates the HUD, roster, kill feed, bases, labels, controls, display panel and result banner together; only the recovery affordance remains. The button and H shortcut use that transition, with interactive keyboard targets excluded.

Playback phone form is shared by both renderers through `usePlaybackPhoneForm()` and `PLAYBACK_MOBILE_QUERY`. Vue rendering and the 3D `.phone-form` root class use this semantic decision; width-only CSS cannot turn an 844×390 coarse-pointer phone into tablet layout. Compact speed/transport, secondary controls and safe areas follow the same phone form; portrait-flow versus landscape side lanes is a separate decision shared through `usePlaybackPortraitViewport()`. Touchscreen tablets with tablet-height viewports keep tablet presentation. `usePlaybackFullscreen()` tracks ownership with `document.fullscreenElement === target()`; concurrently mounted panes never report another target's fullscreen. Only a phone entering its own fullscreen attempts landscape orientation.

Roster presentation has one responsive contract. Non-portrait layouts, including phone landscape/fullscreen and short viewports, keep persistent side lanes with recorder allies left and enemies right; normal 7v7 rows fit without team/lane scrollbars. Portrait layouts use natural document flow: HUD / square Stage / Transport / Display (when open) / inline Details / allies / enemies, with page scrolling rather than separately scrolling team boxes. There is no on-demand transient roster surface. `uiPrefs.showRoster` removes only roster presentation; data, selection, follow target, camera and playback remain unchanged. The renderer keeps its Stage contract when lanes are hidden: 2D remains square, while 3D fills the available center in landscape and remains square in portrait.

`Replay3DPane` owns selected vehicle state. A Three.js raycast reports selection intent through the scene callback; it never owns Vue selection. Scene selection opens the shared `VehicleDetailsPanel.vue`; a 3D roster-row click explicitly follows that vehicle. Follow is an explicit camera command and Free/Top preserves selection. The details panel accepts common identity/HP/time plus optional portrait, last-known/destruction time, stats, track inspector and damage log; 2D and 3D consume the workspace-owned canonical dataset for that evidence. 3D starts from scene identity/HP state and enhances the open panel when canonical data arrives; unavailable sections are omitted, and a canonical failure does not block the scene. The same Details component is draggable and floating across the workspace in non-portrait layouts, including phone landscape/short viewports, and inline after Transport/Display in portrait. Details visibility does not reset/reparse playback or reload assets.

Physical team identity and recorder-perspective presentation remain distinct. Both 2D and 3D roster lanes place recorder allies on the left and enemies on the right through `scene/rosterState.js#rosterLanesFor`; unknown players remain a separate group. `PlaybackRoster` receives `friendlyTeam` and derives friendly/enemy titles and `--color-team-ally` / `--color-team-enemy` colors. Physical `team1` / `team2` keys stay unchanged in the data; without a known recorder team, lane ordering falls back to Team 1 left / Team 2 right and row colors stay neutral. `scene/rosterState.js` owns the roster's state-at-time projection (identity rows built once, `hp` / `dead` reprojected per `t`); label presentation uses the shared Vue component and semantic CSS tokens.

Playback tests follow those ownership boundaries: map/marker/gesture contracts live in `BattleMap.test.js`, control contracts in `PlaybackControls.test.js`, timeline contracts in `PlaybackTimeline.test.js`, HUD/mobile/panel contracts in their focused component suites, detail-panel contracts in `VehicleDetailsPanel.test.js`, and pure projection/clock contracts in `utils/playbackVehicleState.test.js` / `utils/playbackClock.test.js`. Shared playback fixtures live in the testing-only `playbackTestHarness.js`. `BattlePlayback.test.js` and the remaining `BattlePlayback.integration.test.js` cases are reserved for cross-component/domain regressions; presentation cases are not duplicated there.

Source-level CSS guards remain useful for ownership invariants, but final layout behavior is not inferred from CSS text. `npm run test:browser-layout` launches the Chrome/Chromium available on the CI runner, loads the actual shared/PC/tablet/mobile Playback stylesheets, and checks real computed styles / geometry for 1600×900 PC, 1024×768 tablet, 390×844 mobile, plus a cross-form isolation case. This gate runs in the frontend CI before the production build. CSS text cannot show *interaction* truth either, so `npm run test:browser-interaction` covers the complementary half: it loads the real app (router / AppShell / ReplayWorkspace / every stylesheet, with only the Keycloak boundary stubbed), emulates device metrics plus coarse pointer, drives the **real input pipeline** (raw touch / mouse events, never synthetic `click()`), and proves via in-page event records that the real click target **is** the intended control. It covers 375×812 / 390×844 portrait coarse, 740×360 landscape coarse, 1024×768 tablet, 1600×900 desktop, capability switching, unauthenticated login failure visibility + retryability, `duration <= 0` transport unavailability, and portrait→landscape rotation. Its `roster-geometry-*` scenarios additionally drive the real 3D pane: injected roster/kill-feed fixtures, recorder-perspective lane geometry, per-row HP number or fallback percentage inside the bar and non-truncation, the display popover staying inside the visible pane and off the scene centre, per-block toggles actually removing their block, and hide-all-UI being recoverable. Those panel interactions use `clickElement()`, which fuses scroll-into-view, an `elementFromPoint` occlusion check and `el.click()` into a single in-page evaluation — measuring coordinates and then clicking from the driver was flaky while the fixture-injected layout was still settling, and the hit test still runs against real browser layout (transparent overlays and occlusion still fail it).

The UI profile remains presentation-only: `wotb-ui-profile` is the single persistence key, and its derived `data-theme` does not create a separate theme state. Showcase and Classic must use the same components, APIs, and business state.

## Android local-first runtime and capability ownership

Android starts the same Vue application from `http://127.0.0.1:21653/index.html` (APK-bundled GeckoView over the Native LocalRuntimeServer loopback origin since 3.0); the APK contains its chunks, commit-addressed Rust/WASM parser, 2D assets and local shooting inputs. Native owns lifecycle/update, AppAuth PKCE/token state, external file ingress and connectivity; Vue owns routing/product UI/capability gates. Web preserves same-origin transport; Android resolves the server-owned paths — the business API and the Android download surface — to `https://wotbtools.com` and uses Native-provided Bearer tokens, while asset-plane reads (3D assets) stay on the local `/agent-assets` path that the native `AgentAssetProxy` forwards straight to the object storage. Sponsor runtime content is not an asset-plane read: it is injected at build time from a pinned Release asset and ships inside the bundle, so Web and APK each serve it same-origin from their own release artifact. Exact-origin CORS is owned by the production gateway, whose Android-Origin path list in `deploy/tx/Caddyfile` must stay in step (`deploy/tx/validate-caddy-config.sh` asserts the exact list). Bundled frontend and deployed Web frontend are independent release artifacts.

`ReplayWorkspace` retains one selection/session owner and the existing five capability/view mappings. LOCAL data/Rating/2D/shooting inspection remain usable without Internet. ONLINE_REQUIRED 3D/AI/HoF/Profile are still discoverable and gate before mount, auth or request; the reason comes from the shared capability model rather than a network timeout. Disconnect preserves local state and cached Native auth; existing 3D session generations and AI AbortController stop remote work. Reconnect updates availability immediately, resumes a connectivity-blocked 3D/HoF/Profile once, and never automatically submits AI. The full matrix and snapshot source/update boundary live in [`replay-workspace.md`](replay-workspace.md).

### 推荐目录的分批部署兼容

AppShell中的useCreatorAvailability提供唯一的健康能力与公开分类快照，按UP/VIDEO派生类型卡片、列表与总入口可见性。recommendations-v1启用typed API，一次类别快照包含两个类型；只有作品非空时总入口也可见。旧后端回退到UP-only API；creators-v1表示UP技术能力，creators-content-visibility-v1确认公开UP分类为非空子集。无新能力时作品不可进入，不发新接口请求。真实content-admin保留各技术可用类型的空目录和管理入口；tournament-admin不拥有内容域，也不再显示内容管理入口；完整管理字典不回流公开快照。

RecommendationsPage是类型入口，CreatorsPage以type prop复用UP和作品列表；旧creators深链继续直达UP，recommended-videos打开作品，两者属于同一导航栏目。CreatorsConfigPage用recommendationType query选择同一表单/类别管理，VIDEO不展示实力等级。Vue Router拥有类型与分类历史，切换前由路由guard确认放弃脏草稿/图片；保存中阻止切换。useCreators/useCreatorManagement将type纳入请求所有权，过期metadata/list/editor响应不得污染新类型。api/creators.ts集中适配新typed和旧UP wire，不让组件处理endpoint或兼容字段转换。

初次加载、恢复联网、窗口焦点、显式刷新及管理写入ACK触发共享读取；ACK会作废写前请求。失败保留最近成功快照，不伪造空目录或清掉已保存/正在编辑的草稿。公开分类失效后router.replace回全部，保留其他query/hash；管理员空分类不回退。该状态不替代useFeatureGate的网络判断，不轮询、不保存到localStorage，不承诺跨会话实时更新。
