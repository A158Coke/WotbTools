# 热力图修复

3.13.0 起三个热力图片元着色器用 `dFdx/dFdy(vViewPos)` 求几何面法线。着色器声明 `precision mediump float`；移动端 GPU 的 fragment `mediump` 是 fp16，15–500 m 视线空间位置的逐像素导数会被量化到 0 或粗档位，`normalize(cross(...))` 随之退化，热力图出现成片错色/错位。桌面把 `mediump` 提升为 fp32，所以该问题只在移动端可见。

装甲模型在 `loadModels` 中已经 `toNonIndexed()` 并 `computeVertexNormals()`，每个三角形的 `vNormal` 本来就是与点击判定 `hit.face.normal` 同源的几何面法线。本版把三个 shader 改回 `normalize(vNormal)`，并移除不再需要的 `extensions: { derivatives: true }`；桌面行为不变，移动端热力图恢复稳定。源码守卫与 `docs/frontend/architecture.md` 同步更新。

# 强制更新说明

本次按用户指令对 patch 版本抬升强制更新门槛（`ANDROID_MIN_SUPPORTED_VERSION_CODE=3014001`），覆盖“patch 默认不抬门槛”的惯例。理由：3.13.x 起移动端装甲查看器热力图在所有非桌面设备上出现可见错乱，产品要求所有客户端升级后再使用。门槛只随本次 3.14.1 的 publish 写入 production `version.json`；stage 阶段不写。

# 已知未修 / 不在本次范围

- LDPlayer/雷电等模拟器上的 WebGL context lost：雷电 GLES 未实现 `glGetGraphicsResetStatusKHR`，GeckoView 158 调用后主动 `LoseContext(2)`；这是模拟器/引擎兼容性问题，本版不处理，也不声称模拟器兼容。
- 查看器对 `webglcontextlost` 的 UX/重试处理仍缺（context lost 时只重载目标数据、不重建 renderer）。该问题与上面的模拟器兼容性一并留待后续。
- 3D/装甲的最终视觉验收仍由用户在真机完成；本候选不把模拟器结果当真机证据。

本候选继承 [3.14.0](3.14.0.md)；后续 stage、真机验收与 publish 仍按发布规程分别执行。
