# Android 3.0.0

- versionName: 3.0.0
- versionCode: 3000000
- Native Bridge: v3 (origin / transport change; RPC methods, params, results and capabilities unchanged)
- Minimum supported version: raised to 3000000 (3.0.0)
- Version classification: major — the Web runtime is replaced (device System WebView → APK-bundled GeckoView) and the Native Bridge wire contract changes origin, so every 2.x client must update.

The app no longer renders with the phone's System WebView. It ships its own Mozilla GeckoView stable engine (158.0.20261007201254), so every device runs the engine that was tested for the release instead of whatever WebView version the ROM provides. This targets the Android 9 devices that showed broken CSS and whole-app crashes when the WebView renderer died.

What changes for users:

- The bundled pages are served by the app itself from `http://127.0.0.1:21653` (a fixed local port). If that port is already taken (for example by a cloned second copy of the app), the app shows an error page with a retry button instead of loading.
- A page-engine crash no longer closes the whole app: the first crash reloads the current page automatically; a second one within a minute shows an error page with "重新加载" / "使用浏览器版" and a selectable diagnostics line. Background memory reclaim reloads the page silently when the user returns.
- Saved page preferences from 2.x (language, column layout, playback options, onboarding progress, UI profile) are reset once, because they lived in the old WebView profile. Login sessions and received replays are kept (they are owned by the native app).
- The APK is much larger (about 160 MiB of engine for both ARM ABIs, plus the bundled frontend; 2.x was about 15 MB).

Unchanged: the bundled Vue frontend and local WASM parsing, native QQ / Keycloak login through the system browser, replay sharing / opening / folder import, APK self-update, connectivity handling, the declared permission set (GeckoView merges the install-time `WAKE_LOCK` and `MODIFY_AUDIO_SETTINGS` permissions; page permission requests are always denied).

Release prerequisites: the Caddy gateway must allow the exact `http://127.0.0.1:21653` origin before publish (`deploy/tx/Caddyfile` `@androidLoopback`), the real-device acceptance in `docs/android/release-process.md` must pass on an Android 9 device and an Android 13+ device, and `ANDROID_MIN_SUPPORTED_VERSION_CODE` must be set to `3000000` before `publish(version=3.0.0)`. Rollback is a 3.0.x release (see "3.0.0（GeckoView）发布与回滚" in the release process); 2.x is no longer a valid production target after this release.

This document records the candidate scope; staging, real-device acceptance and production publication remain separate release steps.
