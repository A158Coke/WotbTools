# Android 3.4.2

- versionName: 3.4.2
- versionCode: 3004002
- Native Bridge: v3, unchanged
- Version classification: patch — small bug fix. Replay life-state classification now handles
  ammo-rack detonations whose terminal HP sentinel is `0xFFFE` (and the rest of the −1/−2 tier)
  via the new Agent `hp_state` field, plus a routine pin bump. No new functionality, no forced update.
- Minimum supported version: unchanged at the existing 3.0.0 major floor; this bug fix does not
  require a forced update.

The bundled Agent moves to upstream v0.4.9 (`deploy/agent/source.json`: ref
`8dcec2c6463f23116871157ef6d64985875efd67`, asset `wotb-replay-wasm-v0.4.9.zip`, sha256
`b77dbcc4…9758`, verified against the GitHub release digest and the artifact's own fingerprint).
`hp_state` is the authoritative HP-terminal classification: `terminal` covers the whole negative
i16 sentinel family, while payloads without the field keep the legacy semantics (`0x0000`/`0xFFFD`
only, other negatives stay unproven sentinels). The bundled frontend consumes that field end to end
and now **sends** the canonical classification on the AI projection (`hpState` on both
`prop3Health` and `healthEvents`), which the service reads as authoritative
(`HpRawState.fromProjection`) — 2D/3D playback and AI review therefore agree on the same life
state. AI-projection goldens were regenerated and audited against the previous revision: the only
differences are the added `hpState` key on every HP entry plus the engine provenance
(pin `v0.4.8` → `v0.4.9`).

This patch follows 3.4.1 on main. APK staging, device acceptance and production publication remain
separate steps; this document does not assert that 3.4.2 has been staged or published.
