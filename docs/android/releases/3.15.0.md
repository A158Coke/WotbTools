# Android 3.15.0

- versionName：3.15.0
- versionCode：3015000
- 变更等级：minor。bundled armor viewer 的结果卡改为概率链驱动：AP/APCR/HEAT（以及命中首个 Primary 的 HE）用完整命中链的累计击穿概率决定标题、层点颜色与伤害，属于用户可见的判定展示能力调整；不新增或删除产品能力，不构成 breaking change，不升 major。
- Native Bridge：保持 v3，RPC、本地 origin 和通信契约不变；`contracts/android-native-bridge.json` 不改。
- 最低支持版本：保持现行 `ANDROID_MIN_SUPPORTED_VERSION_CODE`，不因本次功能调整强制更新（3.14.2 的强制更新门槛继续生效）。

3.14.2 已取得 immutable release identity（`android-v3.14.2` tag），不能复用来承载新的 bundled frontend；本候选从 3.14.2 递增至 **3.15.0 / 3015000**，只声明新的候选版本，不代表已 stage、已真机验收或已发布。

# 概率结果卡

结果卡以 Armor Inspector 的逐层概率链作为唯一层链：每层用当前穿深区间（Blitz ±5% 视为 ±3σ）计算 CDF，再把区间两端同时平移一次该层 1× 等效厚度；外部模块是 flat 扣除，HEAT 间隙按距离衰减区间。标题、每层圆点颜色（0% 红、1–99% 黄、100% 绿）与总概率同源；任意非零概率都显示该弹种全额伤害，亚 1% 显示 `<1%`。

概率显示边界：`0 < chance < 1` 且四舍五入会得到 100 时显示 `>99%`，只有精确 100% 才显示 `100%`，避免“可能击穿 100%”的自相矛盾。概率归零后仍保留到首个 Primary 的完整层链（后续层统一按 0% 渲染），不再提前截断层行/层点/轨迹终点。

概率模式只在链上存在**正厚度 Primary**（hull/turret/gun 板）时启用：仅命中履带/炮管等外部模块、或 0mm 板终止的射线保持确定性卡片，避免把外部模块的 flat 消耗误读成必穿全额伤害。同名装甲板被射线命中多次时，轨迹点按命中次序（occurrence）匹配，第二块同名板不再复用第一块的命中点。

HE 命中非 Primary 首面时仍走确定性首面爆炸/溅射分支；HE 溅射伤害公式保持 BlitzKit 版本，Armor Inspector 的 HE camera / 半径采样实验未进入本候选（见 `docs/research/armor-inspector-he-damage.md`）。

# 验证

- `armorInspectorChance.test.js` / `penetration.test.js`：概率链完整保留、`>99%`/`100%` 显示边界、`hasPositivePrimary` 前置条件、同名层 occurrence 匹配。
- `browser-armor-aiming.mjs`：真实短按读取结果卡 DOM，断言必穿（绿色、全额伤害）、0%（红色、无伤害）与中间概率区间（黄色、1–99%、全额伤害）三种渲染。
- `browser-armor-mobile.mjs` / `browser-armor-shot-readiness.mjs` 保持通过。
- `HomePage.test.js`：Web 首页 Hero 出现次级 Android 下载按钮并指向 `/download/android`；Android App 内整条 Android 入口不渲染。
- 3D 画面本身仍由用户真机验收；本候选不把模拟器结果当真机证据。
