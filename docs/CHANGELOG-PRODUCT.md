# 产品版本历史

用户可感知的功能变更。技术细节见 `CHANGELOG.md`。

## [Unreleased]

### Added
- **AI 复盘与战局回放不再跳页，解析结果不丢失**：上传并解析回放后，页面下半部分成为可切换的工作区——「解析结果 / AI 复盘 / 战局回放」三个能力原地切换，不再跳转页面，也不用重新上传或重新解析；切走再切回时，AI 复盘进度与结果、战局回放画面原样保留。上传区与回放结果里的「战局回放 / AI 复盘」按钮都会直接在当前页面切到对应视图。

- **百场新增 WG 官方自动认证**：原来的截图 + 5 个回放人工审核完整保留；使用 Wargaming ASIA/EU/NA 登录的玩家可改选“WG 自动认证”，只填写车辆、场均和场数。系统以官方数据核验账号总场次至少 5000、目标车辆至少 100 场；官方精确场均不超过 3900 时自动入榜，超过 3900 时自动生成待审核申请，不要求再次上传截图或回放。管理员只能通过、拒绝或删除，MANUAL 使用原申报值、WG 使用冻结官方快照，均不可改写成绩；WG 暂时不可用时可继续走原人工入口。
- **解析大量回放不再卡住，进度真实可见**：点击「解析预览」后立即出现任务卡片，实时显示「已解析 18/34 场」进度条、当前正在处理的文件、有效/重复/失败数量，并可随时取消；解析期间页面照常可以浏览和操作，完成后自动展示结果。解析完成后点击「合并汇总 / 每场导出」会直接复用已解析的结果生成 Excel（不再重新上传、不再重新解析），导出卡片直接显示「正在生成 Excel…」，大批量导出明显更快。
- **上传区不再被几十个文件名撑满**：选择 34 个以上回放时，上传区只显示「34 个文件 · 47.2 MB」摘要，点「查看文件列表」才展开（内部滚动、长文件名自动截断），需要时仍可继续添加或清空。

- **界面整体重构（V2）**：统一顶部导航——「回放解析」与「AI 复盘」合并为「战局分析」一级入口，更新历史 / 联系我 / 反馈 / 个人中心 / 管理后台收进右上角用户菜单（登录后显示用户名）；回放解析结果页改用近全宽数据工作区，选择具体单场后可直接进入「战局回放」或「AI 复盘」；名人堂改用更宽布局，上传入口改为「提交记录」按钮（弹窗内上传），排行榜成为页面核心；个人中心放宽到 1280px；战局回放 / 地图分析获得更宽工作区。


- **导出大批量回放不再像页面卡死**：点击「合并汇总 / 每场导出」后立即在右下角出现任务卡片，实时显示「已处理 18/34 场」进度条、当前阶段（解析回放 / 生成 Excel / 打包 ZIP）、重复与失败数量，并可随时取消；完成后在卡片上直接下载，导出期间页面照常可以浏览和操作。导出的单场 Excel 文件打开后默认显示「玩家数据」表（不再先看到大片空白的战斗信息表）。

- **百场成绩提交支持会话草稿**：关闭提交弹窗或点击遮罩后，已填写的车辆、场均、场次、截图和回放文件不会丢失；5 个回放可以分多次逐个或批量追加，已选文件会显示在列表中并支持单个移除。提交失败继续保留草稿，只有提交成功或主动确认“清空草稿”才清空；刷新或关闭网页后不保留本地文件。
- **贡献度 / KAST / Impact 直接显示在回放解析结果里**：上传回放后，单场玩家表直接显示每名玩家的贡献度、KAST、Impact（与原来的「战斗表现」同一套算法、同一份回放数据，不需要再进任何额外页面）；多场上传时「汇总」表同样显示跨场贡献度、KAST、Impact、多伤率、互换击杀。删除独立的「战斗表现」标签页。回放无法确定车辆血量时，贡献度与 KAST 显示「—」而不是假的 0%（Impact 不依赖血量，仍显示数值）。Excel 导出的单场/汇总表也同步包含这些列。
- **移除 Rating V2 综合评分，改为「战斗表现」**：不再有任何评分总分（Rating V2 排行、解析页「评分」列、评分规则弹窗、最高评分统计均已移除）；贡献度、KAST、Impact、潜在伤害、协助、击杀、多伤率、存活率、互换击杀等指标改由统一的回放事实管线计算，与战局回放 / AI 复盘共用同一权威事实源。扩展分析页更名为「战斗表现」，接口改为 `POST /api/performance`。
- **战斗表现并入回放解析**：不再有独立的「战斗表现」入口与页面——上传回放后直接在结果页查看贡献度、KAST、Impact、潜在伤害等指标，同一份回放数据同时用于基础战绩与战斗表现，无需重复上传；车辆血量信息未知时相关指标不再猜测（按血量已知的场次计算）。
- **名人堂单场管理不再要求记 ID**：名人堂记录管理页移除了 Arena ID 与车辆 ID 输入，也不再展示原始战斗模式数字；管理员可按国家/系别、车种、等级（都可不选）直接筛选记录并缩小车辆名称，也可从全部已有车辆中选择。
- **战局回放车辆详情增加真实车型图**：点击十级车后，详情面板会显示该车辆对应的 BlitzKit
  透明车型图；图片按需加载，缺图不会影响回放或显示破图。

### Fixed
- **名人堂管理页的「操作日志 / 百场审核」入口重新部署后立即出现**：此前部署新版本后，浏览器可能仍加载缓存的旧页面，导致管理页顶部只有记录列表、看不到「操作日志」与「百场审核」两个 Tab；现在每次打开都会获取最新版本页面，部署即生效。管理员还可通过页面控制台（F12）看到当前前端构建版本（commit 与构建时间）。
- **League 无法评分不再显示成「文件解析失败」**：训练赛/联赛回放未满足评分条件时，结果页不再把它们放进红色「N 个文件解析失败」区域，改为单独的「League Rating · 可评分 X / N · N 场未生成 Rating」汇总提示（琥珀色），点「查看详情」可按原因（名册不完整 / 非标准 7v7 / 平局 等）分组展开、再查看具体回放文件；回放本身解析失败仍显示红色错误。混合上传普通回放与训练赛/联赛回放时也不再整体拒绝：所有能解析的回放都正常展示，League Rating 暂不可用并给出提示。
- **League 回放解析不再被评分条件误伤**：选择训练房/联赛回放并点击「解析预览」时，此前只要有一批回放不满足 League Rating 评分条件（如名册不完整、阵亡时间缺失、平局等），整批会被误判为「没有可用的回放文件」导致解析失败。现在只要回放本身能正常解析就会正常显示结果；无法计算 League Rating 的比赛保留在结果中，并逐场显示具体原因（非标准 7v7 / 名册不完整 / 平局或未知胜方 / 阵亡时间缺失等），Excel 导出的战斗列表同样标注原因，不再出现整批解析失败。
- **首次 WG 登录后可直接提交百场认证**：使用 Wargaming ASIA、EU 或 NA 首次登录后，无需先访问个人中心即可在百场名人堂提交官方认证；系统会自动同步账号资料。账号冲突或身份验证失败仍会安全拒绝，不会创建申请。
- **修改回放文件后不会再用旧的解析结果导出**：解析完成后如果再添加 / 移除 / 清空回放文件，页面会立即回到「未解析」状态并作废旧结果——此时导出会按当前文件重新解析，绝不会把之前那批回放的 Excel 静默当成新文件的导出结果（正在解析中修改文件也不会串结果）。
- **批量导出大批量回放不再乱序、写盘失败不再静默产出坏包**：34 个及以上回放批量导出时，每场导出的 ZIP 包与汇总表顺序严格保持你上传的顺序（此前 10 个以上会按文件名排序打乱，如 0、1、10、11、2…）；导出过程中若磁盘写入失败，任务会明确显示失败并自动清理半成品压缩包，不会留下可下载但损坏的文件；取消排队中任务的统计也恢复正确。
- **AI 复盘恢复可用（事实校验 502 修复）**：此前部分团队回放在真实数据下会因内部结构化校验细节（如 missing claim 类型、证据引用细节）连续重试后失败并显示 HTTP 502，AI 复盘长时间不可用；现在只有真正的用户可见事实错误才会让复盘失败，其余结构化细节不再阻塞输出，错误时也显示具体原因文案（如「未通过事实一致性校验，请重试」）而非笼统的 HTTP 502。
- **名人堂车辆筛选修复**：单场普通页与管理页的国家/系别、车种、等级不再只是缩小车辆候选，也不要求先选具体车辆；任一项都会直接筛选榜单，多个条件按交集生效。百场普通页和管理页的国家/系别、车种也都能独立真实筛选，车辆使用明确下拉选择，不会再选择条件后仍无脑显示全站前十。百场截图和原始回放只在待审核详情提供，通过、拒绝、撤回或删除后立即清理，避免长期占用空间。
- **百场审核和排行榜更易用**：审核列表不再把“通过/删除”直接放在表格中，所有申请与历史记录都先打开“详情”；被拒绝申请现在能看到拒绝原因、说明和时间，待审核详情中才能通过/拒绝，当前纪录详情中才能删除。百场默认展示全站最高 10 条，默认标签改为“默认”；国家/系别、车种无需选择具体车辆即可直接筛榜，并同步缩小 Tier X 车辆候选。
- **战局回放车辆详情面板只显示当前状态**：删除「最大 HP」「HP 百分比」「协助伤害」「最终战绩」分区——血量只显示当前实际值（不再附带 tankopedia 基础血量当最大 HP），整场结算不再混入当前时间点面板；「造成伤害」改为「已记录伤害」，只统计回放可可靠证明的掉血。
- **战局回放伤害数字改为权威掉血**：地图伤害飘字、伤害记录、当前统计改用相邻血量采样推导的实际掉血（如 -377）；无法证明归属的掉血不显示精确数字，来源未知记录显示「来源未知」。
- **战局回放车辆类型恢复正常**：此前几乎所有车辆显示「—」，现在自动使用官方车辆库类型兜底。
- **战局回放击杀播报/击毁动画恢复**：数据链路缺失导致从未触发，现已恢复；面板击杀数不再恒为 0。
- **战局回放密集区域不再大面积叠字**：车辆靠近时坦克名/玩家名/血量数字按优先级让位或隐藏。
- **战局回放伤害/归属口径收严（PR #107 审查）**：伤害数字（地图热力、掉血窗口、对炮明细、占点窗口承伤）全部只使用相邻血量采样证明的实际掉血；攻击者/击杀者归属只在有可靠证据时给出，无法证明的掉血标记为「来源未知」而非猜测。
- **战局回放开局不再显示黑条/空条（PR #107 第二轮）**：己方车辆开局没有实际血量证据时，地图 marker 显示完整己方阵营色血条（100% 相对满血状态）、底部己方总血量条显示 100% 实心阵营色条，车辆详情面板当前 HP 显示「100%」——这是相对状态，不代表具体 HP 数值；一旦回放出现可信的实际血量采样，全部改为显示该精确数字。只有实际进场最大血量已被可靠证明时才计算真实百分比，敌方无可信观测时继续显示未知（—）。
- **战局回放总血量不再把「部分证明」当成精确总数（PR #107 第三轮）**：只有全队每辆车的进场满血量都已被回放证明时，底部总血量条才显示精确分数；只证明了一部分车辆时改为只显示真实已知剩余数字（不显示会误导的「剩余 / 部分总数」分数）；回放观测到的最大血量只来自真实血量采样（没有可信采样就不显示容量参考数字），不再拿坦克百科基础血量当观测值。
- **战局回放己方开局视觉规则收紧（PR #107 第五轮）**：己方车辆在开局（回放尚未出现可证明的掉血/阵亡）一律显示满血实心条——即使已观测到部分车辆当前血量、或全队进场满血量尚未全部证明，也不再显示条纹或黑条；车辆详情面板已有真实血量采样时显示该真实数字、否则显示「100%」（相对状态，不代表具体血量）；首次出现回放可证明的掉血后才切换到精确数字或不确定条纹，回看开局自动恢复满血实心条；敌方仍保持未知（—）。回放出现「当前血量高于已证明进场满血量」的矛盾证据时，不再悄悄改写血量数字，而是如实显示已观测数值并把状态降级为「不确定」。
- **战局回放血量证据一致性收紧（PR #107 第六轮）**：血量显示只有在「全队每辆车的进场满血量都已证明、且回放观测到的血量变化完全自洽」时才显示精确总数——已阵亡车辆历史上的异常血量同样会使全队降级为不确定，血量采样出现「先降后升」或「归零后又回升」也视为不可信；出现矛盾时保留真实观测数值、只把状态降级为不确定，绝不修改血量数据来凑出精确比例。
- **团队 AI 复盘输出格式更稳定**：AI 生成复盘时后端现在强制使用供应商官方 JSON 输出模式（此前只靠提示词要求「输出 JSON」），
  「输出不是合法 JSON / JSON 前后夹带说明文字导致解析失败、需要整篇重新生成」这类情况显著减少——
  团队复盘出结果更快、更少遇到需要 AI 反复重写的情况。事实校验（时间/人数/位置/证据绑定）的安全边界保持不变：
  校验不通过仍然会带着具体冲突让 AI 自行改写，绝不放行与后端事实矛盾的输出。
- **团队 AI 复盘的证据绑定成为硬约束**：AI 每条结构化事实复核条目（claims）引用的证据编号现在必须真正指向支撑这条事实的后端证据——死亡类条目必须引用对应玩家的阵亡证据（身份与时间一致）、人数变化必须引用 before/after 一致的存活变化或关注窗口证据、位置类条目必须引用对应时刻的同一阵营位置快照、敌方位置条目必须引用同一玩家同时刻同区域同知识状态的证据；不能因为「全局恰好存在这个数值/这个变化」就蒙混过关。报告了不存在的证据、借用了其他玩家的阵亡证据、把两辆同车型敌车（如两辆 IS-7）混为一辆、或把「最后已知位置」当当前位置写，都会被拦截并要求重写。

### Fixed
- **团队 AI 复盘事实守护支持中/英/俄三语**：AI 输出的时间、人数、位置、阵亡等事实校验不再只识别中文——英文（如 "WildCat died at 121 sec"、"7 vehicles in region 6"、"full LOS"）与俄文（如 "погиб на 121 сек"、"7 машин в 6-й зоне"、"полная линия огня"）的同类错误同样会被拦截；LLM 的结构化复核条目（claims）改为携带机器可校验字段（时间/区域/数量/归属），三语输出共用同一套机器格式，校验更准确；英文/俄文的合法战术判断与教练建议（如 "the main problem was the first engagement"）不受影响，照常通过。

### Added
- **团队 AI 复盘升级为「自然教练模式」**：复盘正文不再按「核心结论/关键决策窗口/可确认问题/训练建议」固定模板输出，而是像看完录像的教练一样，以 3-5 个自然段落讲清「这局最值得复盘的是什么」——先判断整场最值得讲的 1-2 件事，只有一个决定性问题就只讲一个，不再为了格式完整凑问题数；每场复盘必须有且只有一个明确主判断（这局最主要的问题是什么、为什么、下次改什么），不再出现「可能是A也可能是B」的模糊列举；不确定的具体原因（如谁当时有射界/被哪块掩体挡住）不再影响给出上层战术判断。默认 400–1200 字，简单局更短、复杂局不超过 1500 字。
- **团队 AI 复盘事实一致性守护（后台自动）**：LLM 生成的复盘会先经过后端事实校验再展示——时间窗口内引用的阵亡必须真实发生在该窗口内、玩家阵亡时间与后端一致、人数变化（如 7v7→4v6）不会被写成 3v5、某时刻「7 辆全在 6 区」不会超出该时刻真实位置快照、「敌方最后已知位置」不会被说成「敌方此时就在这里」；没有视野/射界证据时不再出现「进入所有炮线」「具备完整LOS」「被掩体卡住」这类硬事实断言（可写成「更可能/从交换结果看」级别的判断）。校验不通过时后台会带着具体冲突让 AI 自行改写（最多两次），仍失败则明确提示本次复盘无法通过事实校验，绝不把已知事实矛盾悄悄输出。

### Fixed
- **团队 AI 复盘更像真人教练**：团队复盘正文不再机械罗列「发生了什么/为什么重要/能够确认的问题/无法确认/更好的处理」小标题，也不复述 UNKNOWN、canonical、证据标签等后台术语；只在真正影响判断时才说明「无法确定」，其余未知不再逐条列出；默认只分析最重要的 1-2 个关键窗口与 1-3 件要改的事，中文正文默认 600–1200 字（简单局更短、复杂局最多约 1500 字），只保留支撑判断的关键数字，不再重复罗列双方逐车数据。

  全歼与存活推导仅在结算阵容完整（名册与战绩一致）时生效，阵容不完整时不误报全歼。
