# Kranvagn 跳弹续飞噪点：#711 修复证据

2026-10-20，基线 `ef46adcc9d4e86dd68c5fd7830c7201407e437e1`。

## 根因与修复

首板身份保持 `turret_01_armor_1`、triangle 32。CPU 判穿而 GPU 有时无续飞。
把 GPU 实际跳弹起点和反射方向读回后交给 CPU，仍判穿；去掉 Primary 深度预通道
作单次写入 A/B，7 个点的分类不变。因此本次直接修求交，不重构显示管线。

KRV 炮管模块与炮盾板有共面表面。DDA 消费模块后原先执行
`tCur = bestT + ADVANCE_EPSILON`（0.1 mm），把距离相同或紧邻的 Primary 一并跳过。
浮点舍入改变模块/Primary 的先后顺序，造成稳定表面内部的绿紫交替。
现在在候选阶段过滤已消费模块 variant，模块消费后保留 cell 游标，继续寻找其它候选。
同距时统一先消费外部模块、再处理装甲，GPU/CPU/点击续飞不依赖 pack 顺序。
后续实机验收发现，数学共面但使用不同三角形的表面，float32 求交距离并不总是精确相等。
现在以最近 Primary 的射线/三角形运算误差范围确定是否仍需消费模块，不使用固定物理间距
或邻域涂色；模块仍扣穿深并计入层预算。
同时修正 `bestT=hi` 时拒绝恰好命中 cell 窗口上界的问题。

输入与状态修复：5 px 内微动不再瞄准；复制矩阵数值检测姿态变化，所有通道前统一
准备网格，失败统一禁用；点击前更新源矩阵，续飞反射使用实际入射射线。
法线、片元计算与网格边界全程 highp。原始诊断见 [本机测试](../frontend/local-testing.md)。

## 回归与边界

既有 `browser-armor-aiming` 门禁新增微动点击、原始 ID/分类重复读回、非零跳弹
GPU/CPU 对照，以及直接执行 production GLSL 的共面/0.05 mm 间距回归：AP/APCR
转正参数 × 高/低剩余穿深 × 两种 pack 顺序，必须分别判穿/判挡。零样本不能算对照通过。
矩阵快照单测覆盖父级移动、微小变化、相机运动不失效；浏览器门禁将真实模型变为
超大几何使网格连续失败 240 次，再恢复到原成功姿态，必须无需 dirty 标记便恢复续飞。
销毁网格时清除成功姿态快照，避免误用已不存在的网格。射击就绪门禁保护首帧/换车/重试。

上述证据是原始分类与几何输入的数值验证，不是最终画面的人工验收。
需用户在实际设备检查原噪点带、相机微移、DPR/resize、HE 与模块遮挡；
9×9 ROI 不能代表整个未采样楔形区域或所有设备。


## 实机验收补充：低机位车体反射（2026-10-20）

用户提供的后续样本：相机 `(1.4028068637, -1.2443215171, -13.5592972959)`，
目标 `(0,1.9742020071,0)`，FOV 22.0124425867°，点击 NDC `(0.0341643864,-0.0948148600)`。
100 mm 车体板以 80.56° 首次跳弹，剩余 187.5 mm；出射段炮管 50 mm 与炮盾共面，
正确消费后只剩 137.5 mm，小于约 154.9 mm 的等效炮盾，结果应为未击穿。
只比较 `tHit == bestT` 会被不同三角形的舍入差异打破，随机省略炮管，错误翻成绿色。

- 数值复现使用 Intel UHD / ANGLE D3D11；16×16 CSS ROI（DPR=1.5）共 576 像素。
  修复前 GPU 分布 319 绿 / 257 红，存在与同输入 CPU 不符的像素；修复后 104 绿 / 472 红，
  其中 511 个可对拍的续飞像素同输入 GPU/CPU 零差异，其余 65 个为非续飞像素。
  ROI 含真实几何边界，不要求整块全部红色。
- 用户已在实际设备确认残留噪点消失。
- 单样本显示通道曾作为定位实验，用户反馈仍有噪点，已撤回，未作为最终修复提交。
  最终改动仍在碰撞判定，不增加生产 render pass/RT。

误差依据采用 [PBRT 的 ray-aligned triangle 距离误差推导](https://www.pbr-book.org/4ed/Shapes/Triangle_Meshes)：
`gamma(n)=n·2^-24/(1-n·2^-24)`，并计入现有 Moller 距离与该参考求值的差。
CPU 与 GPU 使用同一 float32 口径。仅最近 Primary 的误差定义终止窗口；后方模块自己的
误差不得扩大窗口，每种 variant 只看最近候选。先按几何距离定位锚点，再安排模块，
避免非传递的 epsilon 排序。GPU 在终止前查询窗口穿过的相邻 cell，仍受取数与步数预算限制；
不完整探测保守退出并报告原因。

真实两三角形及射线保存在 `frontend/scripts/browser-fixtures/kranvagn-coplanar.json`，
由 CPU 单测和真实 GLSL 门禁共同消费。GPU 48 组覆盖原始共面、真实 KRV 舍入样本、
模块在前/后 0.05 mm、跨 cell 的 0.8 μm 窗口、斜板跨 cell 中真正更近的模块，
并组合两种 pack 顺序、AP/APCR 转正与高/低剩余穿深。
