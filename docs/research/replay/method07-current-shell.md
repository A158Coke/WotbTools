# Avatar method 0x07 — 服务器确认的当前弹种

> 语料：本机 46 场回放（11.18 ×3、11.19 ×35、11.20 ×8）。
>
> Method id 按实体类与版本限定。

## 结论

```text
Avatar method 0x07 args(5) = [a0 u8][shell_global_id u32 LE]
a0 = 0/1  : 当前弹种（恒同钟同值）
a0 = 18   : 异构子命令，不是弹种
```

> method 0x07（a0=0/1）= **服务器确认的当前弹种，切换即生效 — PROVEN 当前语料**。

线上不存在「已选弹种」与「膛内弹种」两个状态。Type28 是客户端按键，不是当前弹种。

## 证据

| 检验 | 结果 |
|---|---|
| 开火弹种（method17 同钟库存记录）= 开火前最新 0x07 | 406/406，无反例 |
| 已装填后切弹再开火 | 82 次，74 次间隔短于一次装填，最短 0.118s |
| 上述开火的弹速（method29，独立物理证据） | 可区分的 60 发：60 发符合新弹，0 发符合旧弹 |
| a0=0 与 a0=1 | 792 组全部同钟同值 |
| 装填中切弹的装填完成时刻（fire→code0 / 标称时长） | 中位数：有切弹 0.999（n=139），无切弹 0.999（n=235） |
| Type28 → 0x07 确认延迟 | p05 0.10s，p50 0.20s，p95 0.34s |
| 首发前已有 0x07 | 有开火的 43/43 场 |

Type28 与 0x07 的差异：

- 按下已选中的弹种有 Type28、无 0x07；
- 有回放完全没有 Type28，0x07 不受影响；
- Type28 是槽位，要映射才能得到弹种；0x07 直接是 `shell_global_id`。

弹药打空时 0x07 自动切到下一种弹，没有对应 Type28。

## 归属边界

19/46 场在录像者死亡后，0x07 与 method17 跟随被观战车辆（出现本车弹表外的弹种，且无 Type28）。
归属止于录像者首次死亡，与 Type39/23/31 相同。同国车辆可能共用弹种 id，所以不能靠「弹种不在本车弹表」判断归属。
