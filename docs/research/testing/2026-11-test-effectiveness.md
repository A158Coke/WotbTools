# 测试效力审计（2026-11-01）

绑定基线 `1cefa174ca9cde6cc4240e89cb9d93769a2741d2`，属 Issue #740。本文是 dated 证据，不描述当前系统。

## 结论

- 有变异数据的测试绝大多数真实有效：前端 2603/2735、Java 765/856 至少杀死过一个变异。
- 排除「主要被测文件未被变异」后，零检测测试前端剩 2 个，Java 为 0 个。逐条确认后只有 1 个可删，另一个（`api/ai-review.test.ts` 的 older 404 用例）断言真实，保留。
- 没有发现成规模的「只为覆盖率」的假测试。最接近的是 251 个纯源码文本断言，它们混有真实回归守卫，不能直接删，转入 #827。
- 更大的问题是漏测，不是假测：变异存活与无覆盖数量都很高，见 #829。

## 方法

| 问题 | 方法 |
|---|---|
| 抓得住吗 | Stryker、PIT（关闭 bail，取每测试 kill 矩阵）；回退真实 fix 的生产文件、保留测试 |
| 抓到过吗 | `CI / PR` 失败日志提取失败测试名 |
| 文本断言有用吗 | 语义变异与等价重命名探针 |

回退样本：固定 seed 740，从 2026-10-01 起的 fix commit 分层抽取；前端限 pnpm 时期（2026-10-25 起）的 commit。
