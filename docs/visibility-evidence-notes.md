# 可见性证据笔记（真理性门禁 A）：录像者客户端视角的「点亮/失察」是否有可靠事件流证据

> 日期：2026-08-13。探针：`java/wotb-core/src/test/java/com/wotb/core/VisibilitySignalProbeTest.java`（@Tag("probe")，不进 CI，无样本自动跳过）。
> 运行记录：`java/visibility-probe-run.log`（5 样本完整输出）。
> 状态：**VERDICT = PARTIAL** —— 事件流中**不存在**可直接证明「录像者客户端当前点亮该敌人」的标志位；

## 3. 逐候选信号的量化证据

### 3.1 type 4 / type 5 / type 33 —— 服务器实体流生命周期（排除）

语义判定依据（跨 5 样本一致）：

- **本方 7 车**：type5=1@[0.45–0.96s]，type33=1@[0.00–0.22s]，**type4=0**，type-10 从 0.7–1.0s 连续到战斗末。
- **敌方 7 车**：type5 首包 = type-10 首包（如 p2 敌方首进 33.82–54.85s 对应首位置 33.92–54.95s；
  fixture 敌方首进 71.32–142.12s 对应首位置 71.41–142.22s），1–4 次重进；type4=1–4 次。
- **leave ≠ 阵亡**：fixture 存活敌 283127373 leave=2；阵亡敌 283127381 leave=0；283127369 leave@200.42 晚于其阵亡 171.4s。
- **enter/leave 与录像者交火不相关**（S9）：ENTER engaged=0–2/15–25（≤8%），LEAVE engaged=0–1/1–12。
- **距离无固定 AoI 半径**：ENTER 时坦克距离 42–451m（中位 121–169m）、相机距离 27–427m（中位 120–206m），
  同一敌可在 46m（明显在视野内）与 451m 处"进入世界"，→ 非距离/视野驱动。
- **重进与位置流 gap 恢复对齐**（fixture）：283127377 重进@136.12≈gap 末 136.2；283127382 重进@164.41/220.92/244.12
  ≈ 其 3 个 gap 末；但 p1 敌 12183255 位置流**零 gap**却 5 进 4 出 → enter/leave 独立于位置流间隔。

结论：type 5/33/4 是 BigWorld 实体在客户端空间的进入/离开（服务器决定何时向该客户端下发实体数据），
**不是**录像者视角的"点亮/失察"。敌方静止时服务器不下发位置、客户端也不建实体——回放里该敌完全"不存在"，
这与「当前点亮」无关（敌在眼前静止也"不存在"）。

### 3.2 type 7 propId 0/4/8 —— 非双态位掩码（排除）

- propId=4：每车 count 25–472、切换 24–471 次；值在 {0,1,2,3,258,259,514,515,1026,1027,1282,1283,1538,1539,
  2051,2306,2307,2562,2563} 等间跳变——相邻值仅差 1/2（位 0/位 1）或 2^k（256/512/1024/2048），且 0.1–0.5s 连续翻转
  → 引擎/档位/炮闩等状态位掩码。若为点亮双态，同一战每车至多几次翻转且应与位置出现/消失同步；
  实测 201 次翻转与 posStart 时间差从 0.5s 到 200+s 均匀散布，**不同步**。
- propId=0：每车 count 10–254、切换 9–253 次，firstVal=1、lastVal=0 → 高频翻转标志，非"存活/点亮"。
- propId=8：每车 1–3 个，值 8961/10497/2236674 等 → 一次性事件（非流式）。
- propId=3（HP，u16）在敌方实体上存在（受击同步、阵亡归 0）——这是"受击/存活"信号，不是点亮。

### 3.3 交火锚点（候选，可作部分可信点亮时刻）

**锚点 A：录像者命中敌 X（recorder-attacker direct-HP damage @t）** → 5 样本共 35 次，全部对敌方。

| 样本 | 锚点数 | 相机数据 | 相机指向目标(<40°) |
|---|---|---|---|
| fixture | 11 | 11 | 8 (73%) |
| p1 | 6 | 6 | 5 |
| p2 | 6 | 6 | 6 |
| p3 | 7 | 7 | 7 |
| p4 | 5 | 5 | 3 |
| 合计 | **35** | 35 | **29 (83%)** |

其中 4 次相机未指向（夹角 44–136°）的样本多发生在后期（录像者远程狙 / 目标在掩体边缘 / 相机数据冻结段）。
锚点语义：录像者此刻**瞄准并命中** X → X 的位置当时对录像者可见（或数秒内可见后盲射命中旧位）。
**不能证明"当前点亮"的极端情形**：目标失察后数秒内静止不动、录像者朝旧位盲射命中——命中只能证明"位置已知"。

**锚点 B：敌 Y 命中录像者（recorder-victim damage + type26 告警）** → fixture 2/2、p1 6/8、p2 3/4、p3 7/8、p4 3/4
的 type26 在 ±3s 内有录像者受击；但 type26 数量 = 被命中次数的 2.4–14 倍（多为近失/队友区炮弹），payload 无攻击者 eid，
攻击者需由伤害事件归因。该锚点证明"有人朝录像者开火"，**不**证明录像者点亮了对方。

**锚点 C：type 23（录像者开火，0=在飞/1=落地）** → 5 样本 113 次开火，仅 21 次（19%）在 [-0.5s,+2.0s] 窗口内匹配到
recorder-attacker 直接伤害（余为未命中/跳弹/未击穿或非 direct-HP）。开火时刻 + 相机朝向同样构成"录像者瞄准某方向"证据，
但目标 eid 只能靠命中归因。

### 3.4 随录像者观察状态变化的流（部分候选）

- type 31（散布衰减流）与 type 23：仅存在于录像者存活窗口（p3 止于 115.0s=录像者阵亡；p1 止于 189.93s≈阵亡 201.2s 前最后一次开火）。
- type 39（相机 7 floats@120Hz）：阵亡后冻结（p3 后 5 元组冻结、f0/f1 观战旋转）；字段映射见 docs/replay-reverse-engineering.md。
- type 32（25B 逐实体客户端事件，含可变事件字节 0x0a/0x0b/0x0d/0x45… + 8B double）：本方实体事件集中在开局
  （fixture 9–12s），敌方实体事件窗口常与交火贴合（fixture 283127381 t32=[81.12..97.42] 恰为录像者 80.92s 命中至其 97.4s 阵亡；
  p1 12183255 t32=[142.78..204.10] 与其 128–141s 交火段接近）。**语义（点亮提示？命中提示？）无法仅凭回放证明**——

- 观战镜头实体 13185652（仅 p3）：0.2s 出生点 → 1.1s 后静止 (0,0,0) → 录像者 115.0s 阵亡后 119.1/120.9/126.3/133.3/134.1/

## 4. 六条验收对照

| 验收 | 现状 | 判定 |
|---|---|---|
| ①录像者客户端视角相关 | 无直接视角标志；仅 type 23/26/31/39/32 属录像者客户端流（存活窗口内） | 部分（锚点级） |
| ②区分从未/当前/失去/重新观察 | 无法从事件流区分；enterWorld 只反映服务器实体流 | 不满足 |
| ③两模式一致 | 5 样本（随机/训练/supremacy）类型集与结论一致 | 满足（一致性无助于可见性） |
| ④不因静止/断包误报 | gap 聚类必然误报（见 3.5 反例） | 不满足 |
| ⑤解释 recreate/离场/阵亡/战斗结束 | type 4/5/33 可解释实体进出世界；leave≠阵亡；type 31 止于录像者阵亡；type 13/14 定战斗结束 | 满足（生命周期，非可见性） |
| ⑥自动化测试 | VisibilitySignalProbeTest 可重复运行输出全部证据 | 满足 |

## 5. 结论

**VERDICT: PARTIAL** —— 事件流中不存在可直接证明「录像者客户端当前点亮该敌人」的标志位
（type 4/5/33 与 type-10 gap 均为服务器实体流生命周期，type 7 propId=4/0 为状态位掩码，type 8 sub 0/1 为伤害通知）；
**能可靠提供的是交火锚点**：录像者命中敌 X（35 次/5 样本，83% 相机指向目标）与敌命中录像者（type 26+伤害归因），
可构造「部分可信点亮时刻集合」，但覆盖稀疏（每战 5–11 个时刻），且无法证明"当下点亮"（盲射旧位极端情形）。

如需完整时间线可见性，唯一可靠路径是**游戏内录屏标注点亮时刻**做 ground truth，再用其校准候选信号
（enterWorld/leave、type 32 事件字节、相机朝向+视野几何）。
