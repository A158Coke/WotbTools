# 全服联赛直播回放

入口：主导航“联赛积分榜”下方的“联赛直播回放”，公开深链 `?view=league-broadcasts`。
桌面／平板使用侧边栏主栏目，手机使用底部主导航，不在“更多”重复显示。
手机与折叠侧边栏采用三语短标题，完整名称仍供辅助技术读取。
服务器选择卡片配有五种聚焦视角的本地地球 SVG、区服短码和语义底色；国服突出中国主体轮廓，亚服显示亚太，美服显示南北美，欧服以欧洲居中，莱斯塔突出俄罗斯区域。图标是装饰性地域示意，来源见 [`broadcast-globes`](../../frontend/src/assets/broadcast-globes/README.md)。桌面／平板两列，前四张形成 2×2，并按实际页头与固定底栏之外的空间自适应两排高度。第五张莱斯塔继续向下滚动，页脚随内容排列；全部卡片不足两排时才预留页脚空间。手机单列，通常约两张占满首屏内容区；短屏保留最小 200px 高度，允许滚动。两种 Profile 共用同一结构。
地球等比居中填充卡片上半部可用图形区域，右上短码与底部名称保留。亚服的卡片短码及英文名称显示为 `APAC`，内部数据和深链继续使用 `ASIA`。
访客无需登录，真实 `wotbtools-admin` 在同一页面增加管理按钮和表单；积分榜专属
`tournament-admin`、HoF 角色或开发参数 `?admin=1` 不授予本功能管理权限。
后端对每个管理请求独立校验角色。

## 浏览与录入

固定服务器依次为国服、亚服、美服、欧服、莱斯塔（`CN/ASIA/NA/EU/LESTA`）。
层级始终是服务器 → 季赛 → 子赛事分类卡片 → 根节点 → 回放，管理员和访客共用数据与组件。
URL 的 `lbServer/lbSeason/lbCategory` 由 Vue Router 所有，可分享、刷新和前进后退；
根节点首次进入分类时默认收起。无效或父子关系不符的深链回到最后合法层级。

季赛独立于积分榜，填写年份、自由名称和选填开赛日期（仅日期，无具体时刻）。
列表使用横向行，已填日期按日期倒序，未填项放在其后并按创建时间倒序。
季赛可修改年份、名称、日期，服务器在创建后固定。

先建分类，再进入分类创建根节点，最后从根节点旁“＋”录入回放：

| 分类 | 根节点 | 回放分组 |
| --- | --- | --- |
| 积分赛 | 第 1–5 轮，每轮唯一 | 有界小组文本，支持数字或名称，不限于 1–4 |
| 八强循环积分赛 | 八强分类下唯一节点 | 不填写淘汰小组与组别 |
| 八强淘汰赛 | 与循环赛互斥，同一八强根节点 | 小组序号 1–4，默认／胜者／败者组 |
| 四强赛 | 四强分类下唯一节点 | 小组序号 1–4，默认／胜者／败者组 |

创建分类不会自动创建根节点，同类型分类在季赛内复用。积分赛轮次和八强赛制在根节点
创建后不可更改，空节点亦然；需要变更时确认删除并重建，所属分类保留。
八强、四强节点容纳多天回放，不按天拆根节点。

每条回放的标题、HTTP(S) 链接、比赛日期、第几天、视角和前两支队伍必填，可再填两支队伍。
第一支是整段回放追随的队伍，允许 POV 与上帝视角。第几天是正整数，与日历日期独立，
不能套用轮次的 1–5 或淘汰小组的 1–4 上限。根节点展开后按实际比赛日期正序，同日按 ID 排序。
根节点的轮次／赛制由回放继承，表单不能覆盖。

保存直接公开，不设发布按钮或草稿状态。单条回放可编辑与确认删除；删除季赛前显示根节点
和回放数量，删除根节点前显示回放数量。确认时携带最新季赛版本；预览后有其他管理员修改，
返回 `BROADCAST_VERSION_CONFLICT`，须刷新数量后重新确认，防止按过期提示扩大删除范围。

## 封面

封面选填，PNG/JPEG 单张最多 10 MiB，尺寸 16–8192 px、最多 20MP。
服务端检查实际解码结果，不只相信扩展名或声明 MIME。选择图片只产生本地预览，保存时才上传；
取消表单不会上传。编辑明确保留、移除、替换动作，未选新图不会误删旧封面。

文件由 Business API 转传腾讯 COS，回放只引用封面 ID。公开图片接口仅返回仍被回放引用的
READY 封面，桶、key 和凭据不由客户端指定。图片失败时仍可阅读回放信息与打开链接。
Android 通过现有业务 API URL resolver 读取图片，不能把 `/api/...` 当作 APK loopback 静态资源。

业务删除与物理文件回收是两个阶段：删除／替换先解除引用；默认宽限 24 小时、每小时回收。
任务只清理本功能元数据登记的无引用对象，失败保留记录下次重试，不操作模型资产、积分榜证据
或其他前缀。存储配置、权限、版本控制限制和上线验收见
[封面运维说明](../operations/league-broadcast-covers.md)。

## 工程边界与验证

- HTTP SSOT：`contracts/http/openapi.yaml` 的 `Broadcast*` schema。
- 公开 API：`/api/tournament-broadcasts` 索引、`/seasons/{id}`、`/categories/{id}` 和被引用封面。
- 管理 API：`/api/admin/tournament-broadcasts/**`，真实全站管理员，季赛版本保护所有树内写操作。
- 持久模型：Business API 的 tournament 域内 `Broadcast*`，独立 `tournament_broadcast_*` 表，
  不引用积分榜 `TournamentEvent`；Flyway V33 创建结构。
- 前端：`useLeagueBroadcasts` 是公共数据和请求生命周期唯一 owner；API 模块负责 Bearer、错误、
  multipart 与 generated runtime validation；组件负责展示和表单。导航／身份变化作废迟到结果。
- 三语共用 `feature-messages.json`，双 Profile 共用结构和语义 token，无第二套管理页面。

测试覆盖契约 fixture、真实 PostgreSQL 约束／事务／并发、权限、图片实际解码、COS stub 与回收，
以及前端完整层级、导航、表单、撤权和上传失败。无云凭据的自动化测试不证明生产桶权限已接通；
APK 真机、COS 真实上传／展示／回收和生产发布均须按所属运维流程另行验收。
