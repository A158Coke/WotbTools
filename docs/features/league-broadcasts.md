# 全服联赛直播回放

入口：主导航“联赛积分榜”下方的“联赛直播回放”，公开深链 `?view=league-broadcasts`。
桌面／平板使用侧边栏主栏目，手机使用底部主导航，不在“更多”重复显示。
手机与折叠侧边栏采用三语短标题，完整名称仍供辅助技术读取。
服务器选择卡片配有五种聚焦视角的本地地球 SVG、区服短码和语义底色；国服突出中国主体轮廓，亚服显示亚太，美服显示南北美，欧服以欧洲居中，莱斯塔突出俄罗斯区域。图标是装饰性地域示意，来源见 [`broadcast-globes`](../../frontend/src/assets/broadcast-globes/README.md)。桌面／平板两列，前四张形成 2×2，并按实际页头与固定底栏之外的空间自适应两排高度。第五张莱斯塔继续向下滚动，页脚随内容排列；全部卡片不足两排时才预留页脚空间。手机单列，通常约两张占满首屏内容区；短屏保留最小 200px 高度，允许滚动。两种 Profile 共用同一结构。
卡片左上圆角正方形底色块随上半部空间等比放大，地球居中占其边长的75%，保留原来的内边距比例；右上短码与底部名称位置保留。英文名称为 `CN Server / APAC Server / NA Server / EU Server`，亚服的卡片短码为 `APAC`；内部数据和深链继续使用 `ASIA`。
访客无需登录，真实 `wotbtools-admin` 在同一页面增加管理按钮和表单；积分榜专属
`tournament-admin` 或 HoF 角色不授予本功能管理权限。本地开发同样只认真实 token 中的
`wotbtools-admin`，URL 参数不能提升权限。后端对每个管理请求独立校验角色。

## 浏览与录入

固定服务器依次为国服、亚服、美服、欧服、莱斯塔（`CN/ASIA/NA/EU/LESTA`）。
浏览层级为服务器 → 赛事 → 同页展开的子赛事与回放，管理员和访客共用数据与组件。进入赛事后直接读取全部分类与根节点，不再先进入分类卡片详情页；积分赛各轮仍是独立的配置和管理单元。
URL 的 `lbServer/lbSeason/lbCategory` 由 Vue Router 所有，可分享、刷新和前进后退；
根节点首次进入赛事时默认收起。积分赛使用带轮次／回放数量的小标题，各轮独立展开；小标题不增加折叠层级。窄屏保留同一行的展开入口与管理操作，回放内容按条目分隔。带 `lbCategory` 的既有深链在赛事页展开并定位对应分类；无效或父子关系不符的深链回到最后合法层级。

季赛独立于积分榜，填写年份、中文名称、英文名称、选填俄文名称及选填开赛日期（仅日期，无具体时刻）。中英名称必填，各最多100字符；俄文可空、最多100字符，空白保存为null。列表、面包屑、删除提示与回放上下文按当前语言选择名称，俄文未填回退英文。名称保留赛事身份，不按月份强制归入春夏秋冬；回放标题和队伍名称始终保留录入原文。
列表使用横向行，已填日期按日期倒序，未填项放在其后并按创建时间倒序。
季赛可修改年份、三语名称、日期，服务器在创建后固定。V38将旧单名称原文回填中文和英文，不自动翻译或丢弃旧值，管理员可随后补全翻译。

分类、根节点和回放在同一个赛事页管理：先建分类，在其旁创建根节点，最后从根节点旁“＋”录入回放：

| 分类 | 根节点 | 回放分组 |
| --- | --- | --- |
| 积分赛 | 第 1–5 轮，每轮唯一 | 小组号选填；填写时为正整数 1–2147483647，不限于 1–4 |
| 八强循环积分赛 | 八强分类下唯一节点 | 不填写淘汰小组与组别 |
| 八强淘汰赛 | 与循环赛互斥，同一八强根节点 | 小组号选填，填写时为 1–4；默认／胜者／败者组 |
| 四强赛 | 四强分类下唯一节点 | 小组号选填，填写时为 1–4；默认／胜者／败者组 |

创建分类不会自动创建根节点，同类型分类在季赛内复用。积分赛轮次和八强赛制在根节点
创建后不可更改，空节点亦然；需要变更时确认删除并重建，所属分类保留。
八强、四强节点容纳多天回放，不按天拆根节点。

新版积分赛使用数字 `groupNumber`，固定显示“第 N 组 / Group N / Группа N”，不提供自由组名输入。积分赛的组号与淘汰赛的组号上限独立：后者仍为1–4。V39把旧组名归档在 `legacy_group_label`，只将纯数字、明确的“第N组”或“Group N”转换成组号；字母和无法解释的名称不猜编号，保留原文且组号为null。组号允许留空，空值不显示小组标记；填写时仍校验对应阶段的数字范围。历史归档文字保留，不自动猜号。

每条回放的标题、HTTP(S) 链接、比赛日期、第几天、视角和前两支队伍必填，可再填两支队伍。
第一支是整段回放追随的队伍，允许个人视角（POV）与观战视角。第几天是正整数，与日历日期独立，
不能套用轮次的 1–5 或淘汰小组的 1–4 上限。根节点展开后按实际比赛日期正序，同日先按已知开赛时刻排序，未知时刻排在其后；相同时刻或均未知时按 ID 排序。
根节点的轮次／赛制由回放继承，表单不能覆盖。

分类及节点的删除放在各自的“管理”菜单中；积分赛小标题管理整个分类，轮次旁管理单轮，八强／四强菜单同时列出节点删除和整类删除。空分类保留管理入口。

保存直接公开，不设发布按钮或草稿状态。单条回放可编辑与确认删除；删除整个子赛事分类会一并删除该分类的全部轮次／根节点及回放，空分类也可删除，不影响同赛事的其他分类。删除季赛或分类前显示根节点
和回放数量，删除单个根节点前显示回放数量。确认时携带最新季赛版本；预览后有其他管理员修改，
返回 `BROADCAST_VERSION_CONFLICT`，须刷新数量后重新确认，防止按过期提示扩大删除范围。

## 部署与兼容性

部署使用 `/api/health` 的 `broadcast-season-contents-v1` 能力声明，表示后端具备赛事内容快照与分类删除端点。TX1 前端和 TX2 副本均在替换线上文件／容器之前检查实际 Business API 上游；旧健康响应、缺失能力或请求失败会阻止切换并保留旧前端。探测不持锁等待后端升级：后端部署成功后重新运行失败的 Frontend 工作流。原有接口仍保留给旧 APK。

## 封面

封面选填，PNG/JPEG 单张最多 10 MiB，尺寸 16–8192 px、最多 20MP。
服务端检查实际解码结果，不只相信扩展名或声明 MIME。选择图片只产生本地预览，保存时才上传；
取消表单不会上传。编辑明确保留、移除、替换动作，未选新图不会误删旧封面。

文件由 Business API 转传腾讯 COS，回放只引用封面 ID。公开图片接口仅返回仍被回放引用的
READY 封面，桶、key 和凭据不由客户端指定。图片失败时仍可阅读回放信息与打开链接。
Android 通过现有业务 API URL resolver 读取图片，不能把 `/api/...` 当作 APK loopback 静态资源。

业务删除与物理文件回收是两个阶段：删除／替换先解除引用；默认宽限 24 小时、每小时回收。
任务只清理本功能元数据登记的无引用对象，失败保留记录下次重试，不操作模型资产、积分榜证据
或其他前缀。存储配置、权限、版本控制限制和上线验收见
[封面运维说明](../operations/league-broadcast-covers.md)。

## 工程边界与验证

- HTTP SSOT：`contracts/http/openapi.yaml` 的 `Broadcast*` schema，仅保留现代三语及时间结构。
- 赛事同页读取：`GET /api/tournament-broadcasts/seasons/{id}/contents` 返回同一 repeatable-read 快照中的 `season/categories/nodes/defaultTimeZone/replayStarts/coverUploadAvailable`；子类型复用现有契约。分类整类删除使用管理路径 `categories/{id}/deletion-preview` 与 `DELETE categories/{id}?expectedVersion=...&confirm=true`，复用季赛锁和封面解除引用流程。
- 公开 API：统一 `/api/tournament-broadcasts`、`/seasons/{id}`、`/categories/{id}`。分类返回既有 `BroadcastTimedCategoryView`，包含 `data`、`defaultTimeZone`、`replayStarts`，不重新设计字段；封面路径保持 `/api/tournament-broadcasts/covers/{id}`。
- 管理 API：统一 `/api/admin/tournament-broadcasts/**`；回放保存使用既有 `BroadcastTimedReplaySave`，明确传 `replay` 与 `startsAt`。真实全站管理员角色及赛事版本保护所有树内写操作。旧版本路径、旧单名/文字小组请求及对应格式转换已移除。
- 持久模型：Business API 的 tournament 域内 `Broadcast*`，独立 `tournament_broadcast_*` 表，
  不引用积分榜 `TournamentEvent`；Flyway V33 创建结构，V38增加三语名称，V39规范小组号，V40初始化已核实分场回放。
- 前端：`useLeagueBroadcasts` 是公共数据和请求生命周期唯一 owner；API 模块负责 Bearer、错误、
  multipart 与 generated runtime validation；组件负责展示和表单。导航／身份变化作废迟到结果。
- 三语共用 `feature-messages.json`，双 Profile 共用结构和语义 token，无第二套管理页面。

测试覆盖契约 fixture、真实 PostgreSQL 约束／事务／并发、权限、图片实际解码、COS stub 与回收，
以及前端完整层级、导航、表单、撤权和上传失败。无云凭据的自动化测试不证明生产桶权限已接通；
APK 真机、COS 真实上传／展示／回收和生产发布均须按所属运维流程另行验收。

## 赛事术语与名称纠正（V41）

界面用赛事 / Tournament / Турнир 表示外层自由命名赛事；内部 season API key 保持兼容。

中文视角采用个人视角（POV）与观战视角（OBSERVER）。比赛日期 matchDate 仍必填，赛事开赛日期 startDate 仍选填；开赛日期不能代替每条回放的比赛日。

V41 只纠正国服 2025、中文“战火杯”、仍为旧默认英文“Zhanhuo Cup”且关联 V40 官方视频分 P 的记录，改为 Blitz Professional Cup (BPC)，同步递增版本以使旧编辑草稿触发冲突检查。自定义中英名称、俄文翻译与回放事实保留；重复执行不再次更新。V40 与 seed-ready.json 是原始核验快照，不改历史内容或哈希。

## 开赛时刻与时区（V42）

赛事开赛日期仍是选填的日历日期。每条回放的比赛日期必填，具体开赛时刻选填；没有可靠时刻的历史回放不补00:00。有时刻时用UTC瞬间保存到nullable `match_starts_at`，`matchDate`保持该区服赛程当地比赛日。

公众回放列表的时区选择器位于标题工具栏，以时钟图标和当前选项组成单行控件，与返回、刷新按钮等高；保留原生下拉、键盘焦点和辅助名称，窄屏限制在可用宽度内。默认区服赛事时区：CN/ASIA UTC+8、NA PT（PST/PDT）、EU CET/CEST、LESTA莫斯科UTC+3；可切其他显示时区。按记录发生日期处理夏令时与跨日，仅改显示，不改数据库、第几天或轮次。纯日期记录不随时区换日。

管理员日期/时间旁的录入时区默认UTC+8，可选择明确UTC偏移；与公众显示偏好分开。切换录入偏移保持同一瞬间。有时间时保存所对应的区服日历日；清空时间保留日期精度。

分类与时间写入在统一路径上继续使用最新时间 envelope/payload，复用既有目录数据主体、业务服务、权限与版本锁。`startsAt` 必须显式提供，可为 null；明确清空时刻仍保留原区服比赛日，除非管理员主动改了日期。原封面路径与上传流程共用。

## 停止旧 APK 支持与部署切换

清理分支只统一路径并移除旧格式适配，不改变既有现代数据结构与初始化事实。此前临时读取回退和客户端旧区服时区映射随旧路径一并删除；新的时区始终来自服务端。

清理 PR 合并前先确认 #672 的生产后端运行提交 `676d25074e82c1650e6d1a0446b1fd4f450dcf7a` 或包含它的更新提交、Flyway 至 V44、实际分类时间接口可读。CI 通过不等于部署成功。

统一路径仍需安排前后端切换：现有网页请求版本路径，更新后的网页不能读取原路径上的旧单名结构。因此合并前须明确切换顺序；清理版后端和网页部署都成功并完成公开目录、分类、管理录入验收后恢复使用，内部测试客户端使用新候选。任何一端失败时恢复成对的已验证版本，避免把半套版本当作可用发布。不得仅凭 #672 后端已上线，就认定清理版本可以无条件独立部署；本次不抬最低支持版本，也不宣称旧接口仍可使用。

## 2025–2026 核实回放初始化（V43）

V43 从 [核验快照](../research/broadcast-seed-2025-2026/seed-ready-2025-2026-verified.json) 新增 71 条回放、19 个区服赛事：2025 年 25 条、2026 年 46 条，分布为 APAC 14、EU 38、NA 15、Lesta 4。V40 已有的国服 3 条另行保留。每流选取一场有证据的两队对局；赛事名称填完整中／英／俄三语，原赛事名称保存在 `sourceSeasonNames`，视频原标题保存在 `sourceTitle` 和证据中。未知组号为 NULL；循环阶段不填组号，官方小组证据仍保存在研究快照。

证据包括视频标题/简介、用户及浏览器准备房间画面、官方完成对局和对应整日转播。整日解说转播按同赛事、阶段、当地赛日及直播区间关联一场已完成对局，快照明确标记该推断，不声称逐帧核验。官网 `stream_group_id` 是观看奖励直播组，不冒充比赛小组。Lesta 只收已对应末日三强/决赛的记录，不把整个六队阶段套为四强赛。

同一杯赛的 Challengers / Middle Echelon 使用带层级身份的独立赛事名称，不与 Professionals 合并目录。2025 Diamond Cup 的部分 Top6 / Top5 视频标题指整体晋级资格层级，官网明确对应的第二阶段实际为四队双败；按所选对局的官方阶段收纳。第几天按各子阶段起止日确定，不把“总决赛”一律设为第 3 天。

直播真实 UTC 开始时间仅用作区服比赛日证据，不写成所选战斗的具体时刻；本批 `match_starts_at` 全为 NULL。管理页仍可录入另行确认的具体战斗时间。移除旧记录时刻时，若未主动修改日期则恢复原区服比赛日，避免 UTC+8 录入跨日造成错日。

与既有初始化相同，先按视频来源识别管理员已有归属，保留自定义名称、翻译和回放事实；来源归属冲突、错误区服/年份或重名歧义时跳过对应赛事；既有根节点赛制不同则跳过对应回放，不把循环赛混入管理员淘汰赛。重复执行不重复新增。其余候选不自动导入，后补使用新迁移或管理员界面，V40 等历史快照与迁移保持原样。核验范围和官方来源见 [复核记录](../research/broadcast-seed-2025-2026/2026-recheck.md)。

## 初始化名称与标题本地化（V44）

本批 19 个新增赛事及原有国服战火杯均提供中／英／俄名称；无法确认官方本地化名称时采用编辑翻译，不冒充官方译名。例如“闪击大师赛：传承 / Blitz Masters: Legacy / Blitz Masters: Наследие”；Lesta 使用“闪击积分联赛·第4期·第I赛季 / Blitz Point League — Part 4, Season I / 原俄文名称”，保留期数、赛季及总决赛身份。
